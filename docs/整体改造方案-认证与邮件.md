## 1. 背景与目标

项目已从图书管理系统演化为「数智游民创新工场」社区官网，面向真实使用者。现有认证体系保留了大量低安全设计（无密码、姓名+证号登录、注册即登录、30 分钟固定会话、无找回/登出/审计），邮件通知则是硬编码模板 + 启动时环境变量绑定（改配置需重启）。本方案将两者整合为一次整体改造：

1. **认证现代化**：证号 + BCrypt 密码、邮箱验证、三步注册、14 天滑动会话、找回/登出/多端管理、登录审计、频控加固
2. **邮件可运营化**：SMTP 账号/授权码/模板后台可视化配置，改完即时生效；验证码邮件成为认证体系的基础设施
3. **业务连续性**：前台匿名接口契约（`X-Session-Token`）不变，存量成员平滑迁移

## 3. 邮件模块设计

### 3.1 数据模型（`mail_config` 单行 + `mail_template`）

**`mail_config`**：`enabled` / `host`(默认 smtp.qq.com) / `port`(默认 465) / `username` / `auth_code`(AES) / `from_name` / `update_by` / `update_time`

**`mail_template`**：`code`(PK) / `name` / `subject` / `content`(TEXT) / `status` / `remark`(占位符说明) / `update_by` / `update_time`

### 3.2 模板清单（10 个，含认证新增 2 个）

| code | 场景 | 占位符 | 说明 |
|---|---|---|---|
| `register.success` | 注册成功 | `{readerName}` `{cardNo}` | 新；**只发证号，绝不含密码明文** |
| `reissue.notify` | 补办证号 | `{readerName}` `{cardNo}` | 新 |
| `auth.code` | 验证码邮件 | `{code}` `{minutes}` | 新；注册/找回/改邮箱共用 |
| `borrow.success` | 报名成功 | `{readerName}` `{bookName}` `{dueDate}` | 迁移 |
| `renew.success` | 续期成功 | `{readerName}` `{bookName}` `{dueDate}` | 迁移+修主题 bug |
| `reserve.success` | 候补成功 | `{readerName}` `{bookName}` | 迁移 |
| `reserve.available` | 有名额通知 | `{readerName}` `{bookName}` `{days}` | 迁移；3 天写死→`{days}` |
| `reserve.cancel` | 候补超时取消 | `{readerName}` `{bookName}` | 新（D6） |
| `purchase.pass` / `purchase.reject` | 入驻审核结果 | `{applyName}` | 迁移 |

### 3.3 动态 SMTP

- 优先级：**数据库 `mail_config` > 环境变量/application.yml > 内置默认**；未做管理操作时行为与现在完全一致
- `MailUtil` 弃用 `@Value` 启动绑定，每次发送前读配置**动态构建 `JavaMailSenderImpl`**（QQ 465 SSL 参数照搬），改完即时生效不重启
- 保留"尽力而为"定位：异步线程池、失败仅日志、`enabled=false` 全跳过
- 新增 `sendTestMail(to)`：管理页测试发送按钮用，验证配置连通性，不回写

### 3.4 后台 UI（`ruoyi-ui/src/views/system/mail/`，菜单"系统管理 → 邮件通知"）

- Tab1 SMTP 配置：开关/主机/端口/邮箱/授权码（"已配置，留空不改"交互，不回显明文）+ 测试发送
- Tab2 模板管理：列表 → 编辑（主题/正文/占位符提示）
- 权限：`system:mail:config` / `system:mail:template`（sys_menu 插入）

## 4. 认证模块设计

### 4.1 凭证模型

- `reader.password_hash`：BCrypt（强度 10）；登录 = `cardNo + password`
- 错误统一"证号或密码不正确"（不暴露证号是否存在，防枚举）
- 密码策略：≥10 位、至少 3 类字符（大小写/数字/符号）
- **证号仍是业务标识**：报名/候补/个人主页关联不变；生成逻辑（SecureRandom 8 位）不变
- 邮箱唯一索引 `uk_email`（先查重清理存量再建）

### 4.2 三步注册（替代"注册即登录"）

1. **提交资料+密码**：姓名/手机/类型/邮箱 + 密码强度校验 → 落库 `pwd_set=1, email_verified=0` → 发验证码邮件
2. **邮箱验证**：`verify-email`（code 校验通过 → `email_verified=1`）；`resend-code` 频控（同邮箱 60s 一条、同 IP 每日 10 条）
3. **完成**：注册成功邮件（模板 `register.success`）只发证号 → 引导登录
   - 未验证邮箱的账号可登录，但登录时要求 `email_verified=1`（未验证则提示先去验证），保证账号可回收
   - 验证码：6 位数字，15 分钟有效，Redis 存储，验证一次即作废

### 4.3 会话体系（`ReaderSessionServiceImpl` 重构）

| 项 | 方案 |
|---|---|
| 有效期 | 14 天**滑动续期**（每次鉴权成功刷新 TTL）；`reader.session.minutes` 入 sys_config 可配 |
| 登出 | 新增 `POST /logout`（删除 Redis token） |
| 多端 | token 附带 `lastLoginIp/lastLoginTime/device`，`GET /sessions` 列表、`POST /sessions/revoke` 退出其他设备 |
| 敏感操作 | 改密码/改邮箱前需重新验证（当前密码或验证码） |
| 401 处理 | 前端统一清 localStorage 跳登录 |

### 4.4 找回密码

- `POST /forgot-password`（证号）→ 发邮箱验证码（模板 `auth.code`）
- `POST /reset-password`（验证码 + 新密码，一次有效）→ 强制重新登录
- 停用/挂失账号不发验证码

### 4.5 验证码通道抽象（短信预留，D1）

```
VerificationSender 接口（sendCode(target, code, ttlMinutes)）
├── MailVerificationSender   —— 邮箱通道（实现，走邮件模板 auth.code）
└── SmsVerificationSender    —— 短信通道（预留：接口已定，bean 未注册；
                                接服务商时实现 + sys_config sms.enabled=true 即可）
```
验证码服务 `AuthCodeService`：生成/校验/作废/频控，与通道解耦；手机号通道默认关闭。

### 4.6 安全加固

- 登录频控三层：**IP 限速 10 次/分**（Redis 计数）→ **账号 5 次失败锁 30 分钟**（现有保留）→ **失败递增退避**（1/2/5/15 分钟档位）
- 注册频控：现有 IP 维度保留；加证号/邮箱维度防撞库
- 登录/登出/改密/重置/失败全部写 `reader_login_log`（后台可查）
- HTTPS：部署指南补反代 TLS 说明

### 4.7 存量迁移（D4）

- `pwd_set=0` 账号调登录接口 → 返回专用状态码 `AUTH_SETUP_REQUIRED` → 前端引导「邮箱验证码 → 设置密码」（以已验证邮箱证明身份）
- 管理员后台新增"重置密码/发送设置密码邀请"（`system:reader:resetPwd`）
- 旧"姓名+证号"登录路径**直接删除**，不留双通道

## 8. 风险与回滚

| 风险 | 对策 |
|---|---|
| 存量成员无法登录 | 引导流程保底（邮箱验证设密码）；管理员可代发邀请/重置 |
| 邮箱唯一索引冲突 | 建索引前查重脚本清理，冲突数据先标记停用 |
| 授权码泄露 | AES 加密 + MAIL_SECRET_KEY 环境变量；UI 不回显 |
| 验证码邮件进垃圾箱 | 模板用 `auth.code` 标准文案；部署文档注明 SPF/DKIM 建议 |
| 邮件配置改错导致全站通知瘫痪 | 测试发送按钮事前验证；`mail_config.enabled` 一键关闭降级 |
| 改造期间回滚 | 两模块改动集中于新表/新列（除登录路径删除项），SQL 幂等可重跑；登录路径删除为不可逆项，验收后执行 |

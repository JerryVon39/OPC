## 一、功能性故障（P0 —— 用户直接受影响，优先修复）

### 1. 登录/注册参数名写错，8 个页面登录注册完全不可用 🔴

- **位置**：`article.html:204,242`、`about.html:234,272`、`industry.html:236,274`、`join.html:224,262`、`news.html:229,267`、`policy.html:261,299`、`talent.html:189,227`、`service.html:212,249`
- **问题**：提交的是 `new URLSearchParams({ name: name, cardNo: card })`，而后端 `ReaderController.login/register`（ReaderController.java:110,154）绑定的参数名是 **`readerName`**。Spring 按参数名绑定，`name` 不会被接收 → 后端永远返回"请输入姓名和借书证号"/"请填写姓名、手机号和读者类型"。
- **影响**：这 8 个页面上登录和注册 **必然失败**；只有 home.html 和 services.html 用了正确的 `readerName`。冒烟测试（smoke_official.py 用 `readerName`）测不到页面层，所以没被发现。
- **引入**：`0a34cbfd`（service.html 详情页独立化）、`60f217d6`（7 个内容页补登录弹窗）——复制弹窗时手误。
- **修法**：8 处 `name:` 改为 `readerName:`。根治：抽公共 `shared.js`（见第 26 条），杜绝继续双版本漂移。

### 2. `goAdmin` 被嵌套进 `submitLogin` 内部，7 个页面"后台管理"点击报错 🔴

- **位置**：`article.html:213`、`about.html:243`、`industry.html:245`、`join.html:233`、`news.html:238`、`policy.html:270`、`talent.html:198`
- **问题**：`function goAdmin() { location.href = '/index'; }` 被粘贴进了 `submitLogin()` 的成功分支里，成了函数局部声明，不会挂到全局。导航"更多"菜单里的 `onclick="goAdmin()"` 点击即抛 `goAdmin is not defined`。
- **影响**：7 个栏目页的"⚙️ 后台管理"入口完全失效。（home/services 两页是顶层定义，正常。）
- **修法**：把 `goAdmin` 移到脚本顶层。

### 3. home.html 残留服务列表死代码，多条路径抛 TypeError 🔴

- **位置**：`home.html:593,607,622,629,638`（`document.getElementById('bookGrid').innerHTML = ...`）；触发点：`:13`（logo `onclick="resetAll()"` → `resetAll` → `loadBooks`）、`:798`（登录成功后）、`:815`（logout）
- **问题**：04 服务区块静态化后页面里已没有 `id="bookGrid"` 元素（已验证 HTML 中无此 id）。初始化序列恰好没调 `loadBooks` 所以首屏不炸，但**点 logo、登录成功、退出登录都会抛 `Cannot set properties of null`**——logo 点击完全失效。
- **修法**：删除整段死代码（`loadBooks/renderBooks/optimisticBorrow/optimisticReserve/openReserve/resetAll` 及相关常量），logo 改为滚回顶部或跳 `home.html`。

### 4. 栏目页登录态显示用错字段，且全站 7 页没有登出入口 🟠

- **位置**：`article.html:225`、`about.html:255`、`industry.html:257`、`join.html:245`、`news.html:250`、`policy.html:282`、`talent.html:210`
- **问题**：
  - 显示用 `currentUser.name`，但后端返回字段是 `readerName`（ReaderController.java:143）→ 即使修好第 1 条也只会显示兜底值"成员"；
  - 已登录状态点击自己名字弹出的是"成员注册"表单；
  - 这 7 个页面没有任何登出途径（home/services 有 `logout()`）。
- **修法**：改为 `currentUser.readerName` 并提供退出按钮（清 `localStorage.shopUser` 即可，与 home 一致）。

## 二、安全与隐私（P1 —— 公网部署前必须处理）

### 5. data_snapshot.sql 含真实个人信息，且已推送 GitHub 🔴

- **位置**：`sql/data_snapshot.sql:26`（reader 表）、`:37`（book_reserve 表）、book_purchase_req 行
- **问题**：pre-commit 钩子每次提交自动导出**全库业务数据**入库，其中含项目作者真实账号（姓名 + 手机号 `123****8901` + 邮箱 `j***@qq.com`，备注"项目作者账号"，此处打码）。仓库已推送至 `github.com/JerryVon39/OPC`（master 与 origin 同步）。**今后任何真实成员在前台注册，其姓名/手机号/邮箱都会被自动提交并推上 GitHub。**
- **修法**：
  - 短期：快照导出排除 reader/book_purchase_req 的敏感列，或只导出演示数据（mysqldump 加 `--where` 或导出后脱敏）；
  - 长期：数据快照机制改为不进 git（或仅导出结构+字典），真实数据走数据库备份；
  - 若仓库公开，考虑清理 git 历史中的该文件（BFG/filter-repo）。

### 6. JWT 签名密钥默认值硬编码进仓库 🔴

- **位置**：`ruoyi-admin/src/main/resources/application.yml:115`、`docker-compose.yml`（backend TOKEN_SECRET 默认值）
- **问题**：`${TOKEN_SECRET:-25a96a...}` 的回退默认值已提交到（可能公开的）GitHub。当前 `.env` 与 `.env.example` 内容完全一致（`TOKEN_SECRET=` 为空）→ compose 的 `:-` 对空串也回退默认 → **现部署正在使用公开可查的密钥**。任何人可伪造 admin JWT 接管后台。
- **修法**：`.env` 里设置强随机 TOKEN_SECRET；后端启动时校验密钥等于已知默认值则拒绝启动（fail-fast）。

### 7. sessionToken 经 GET 查询串传输 🟠

- **位置**：`home.html:497,510,888,947`、`services.html:299,312,713,772`、`service.html:280,291`
- **问题**：会话凭证拼在 URL 上，落入 Nginx/后端访问日志、浏览器历史与代理缓存（旧报告 H1，未修）。
- **修法**：改自定义 Header（如 `X-Session-Token`）或 POST body 传递；resolve 时滑动续期（当前固定 30 分钟无滑动，localStorage 里的 token 很快失效也是体验问题）。

### 8. CORS 全开放 🟠

- **位置**：`ruoyi-framework/.../config/ResourcesConfig.java:61`（`addAllowedOriginPattern("*")`）
- **问题**：任意来源可携带凭证跨域调用 API（旧报告 H6，未修）。演示可接受，公网部署需收窄为自身域名。

### 9. 匿名注册 / 入驻申请接口无频控 🟠

- **位置**：`ReaderController.java:152-178`（register）、`BookPurchaseReqController.java:62-69`（apply）
- **问题**：login/applyReissue 有 IP 频控，但 register 和 purchase/apply 没有——脚本可无限刷库（register 直接插 reader 行；apply 有同名去重但换个名字即可绕过）。DB 会被灌垃圾数据，且这些数据又被第 5 条的钩子自动推上 GitHub。
- **修法**：复用 `readerSessionService` 的频控（按 IP 计数），必要时加简单验证码。

### 10. 匿名列表接口 pageSize 无上限 🟢

- **位置**：`TableSupport.java:45`（pageSize 直传 PageHelper，无上限）；`BookController.list`、`CmsArticleController.publicList` 等 @Anonymous 分页接口
- **问题**：`?pageSize=1000000` 可拖垮 DB。修法：PageDomain 里给 pageSize 设上限（如 100）。

### 11. 默认口令链条完整公开 + 数据库端口暴露宿主机 🟠

- **位置**：`docker-compose.yml`（3306/6379 ports 映射宿主机；MYSQL_ROOT_PASSWORD 默认 password）、`sql/ry_20260417.sql`（RuoYi 默认 admin/admin123 BCrypt 哈希）、README/部署指南明文标注 admin123
- **问题**：公网服务器上照文档部署 = root/password 的 MySQL、无密码 Redis、admin/admin123 后台全部暴露。文档已自我声明"公网必须改"，但没有强制手段。
- **修法**：compose 中 3306/6379 改 `expose` 不映射宿主机；首次启动强制改密或启动脚本检测弱口令告警。

### 12. updateMyInfo 仅凭会话即可改手机/邮箱（旧报告 H5，未修）🟡

- **位置**：`ReaderController.java:237-276`
- **问题**：姓名+证号即凭证的设计下，拿到会话即可接管通知渠道（邮箱用于接收报名/候补通知）。无短信/邮件二次验证，属设计局限，先记录。

### 13. `/system/config/configKey/{key}` 匿名可读任意配置键 🟡

- **位置**：`SysConfigController.java:73-79`（@Anonymous 无白名单）
- **问题**：当前库内键值无害（如 book.stock.warn=3），但管理员日后存入敏感参数即泄露。修法：匿名路径加键名白名单。

## 三、SEO 与内容一致性（P2）

### 14. robots.txt 全站禁止抓取，与官网定位自相矛盾 🟠

- **位置**：`ruoyi-ui/public/robots.txt:2`（`Disallow: /`）
- **问题**：各页精心写了 title/description，搜索引擎却完全不收录。
- **修法**：允许抓取前台页，仅排除 `/prod-api`、`/index`（后台）、`/profile`。

### 15. meta description 含未转义 ASCII 双引号，content 属性被截断 🟠

- **位置**：`home.html:7`、`about.html:7`、`industry.html:7`、`talent.html:7`
- **问题**：描述文案里的引号实际是 ASCII `"`（字节 0x22 已验证），HTML 解析时 content 属性提前截断，后半段变成非法属性——SEO 描述残缺且 HTML 不合法。
- **修法**：换成中文引号「」或 `&quot;`。

### 16. 后端用户可见文案残留大量「图书」措辞 🟡

- **位置**（约 40 处，均为前台会弹出的消息/邮件）：`BorrowRecordServiceImpl.java:88,92,96,164,257,271,299-301,406,441,473,492`（"图书不存在"、"请输入借书证号"、邮件标题"【图书借阅】续借成功"、"【图书预约】您预约的书到了"等）、`BookReserveServiceImpl.java:104,146`、`BookPurchaseReqServiceImpl.java:48`（"请填写书名"，而前台表单语义是"项目/组织名称"）、`BookController.java` @Log 标题"图书信息"
- **问题**：官网语境是"服务报名/入驻申请"，用户报名失败却看到"图书库存不足，无法借出"，观感割裂。
- **修法**：统一替换为"服务/名额/成员编号"话术（纯字符串替换，低风险）。

### 17. 首页硬编码文章链接 🟢

- **位置**：`home.html:219`（`href="article.html?id=11"`）
- **问题**：当前种子数据 id=11 恰为省级政策文，但重建库/删除文章后即 404。修法：按栏目动态取，或至少在运维文档标注依赖。

### 18. 占位内容未替换 🟢

- 各页页脚及 `home.html:258,286`：`contact@example.com`（TODO #17 [待补]）；政策原文部分链接仍指向官网首页（TODO #19）。上线前替换。

## 四、体验细节（P3）

### 19. 7 个页面共享脚本写在弹窗 DOM 之前，点遮罩关不掉弹窗 🟡

- **位置**：`article.html:266` 及 about/industry/join/news/policy/talent 同模式
- **问题**：`document.querySelectorAll('.modal').forEach(...)` 执行时 `#loginModal/#regModal/#toast` 还没被解析（它们在脚本之后），绑定落空。service.html 顺序正确。
- **修法**：脚本移到 `</body>` 前，或改事件委托。抽 shared.js 时一并解决。

### 20. services.html 分类 Tab 渲染未过 esc 🟡

- **位置**：`services.html:563-567`（dictValue/dictLabel 直接拼 innerHTML）
- **问题**：违背全站"库数据插值前必过 esc"纪律（banner 同类数据都转义了）。风险低（管理员维护的字典），但应补齐。

### 21. toast 层级低于弹窗遮罩 🟢

- **位置**：`css/site.css:134`（toast z-index:999）vs `:137`（modal z-index:1000）
- **问题**：弹窗打开期间的提示（如"候补已取消"）被遮罩压暗。修法：toast 提到 1100。

### 22. service.html 详情查找有 100 条上限缺陷 🟢

- **位置**：`service.html:379-382`（拉 `pageSize=100` 全量再 find）
- **问题**：第 101 条及以后的服务详情显示"服务不存在或已下架"。修法：后端提供公开详情接口 `book/{id}`（顺带让首页硬编码 id=11 一类问题消失）。

### 23. 中等宽度下分类吸顶条钻到导航底下 🟢

- **位置**：`css/site.css:569`（`.svc-top-tabs sticky top:60px`）vs `:186-194`（769~1500px 导航换行高度远超 60px）
- **问题**：该区间滚动时 tabs 被 z-index 900 的多行导航遮挡。修法：媒体查询内同步调大 top 或改 static。

### 24. 本地 dist/ 是过期产物，仍含 shop.html 旧链接 🟢

- **位置**：`ruoyi-ui/dist/`（8-21 10:00 构建，早于改名提交）
- **问题**：dist 不进 git、Docker 构建会重新 npm build，**不影响部署**；但本地若直接开 dist 文件预览会看到旧站，易混淆。修法：删掉本地 dist 或重新构建一次。

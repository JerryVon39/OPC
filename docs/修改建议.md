# 数智游民创新工场官网 · 功能删减与新增建议


## 一、概述

本文档基于项目 README 现有功能，从“AI OPC 生态社区官网”的定位出发，提出功能的删减与新增建议。

### 改造原则

1. **聚焦定位**：一切功能围绕“服务潜在入驻者”和“赋能已入驻OPC”展开
2. **砍掉冗余**：移除从“图书管理系统”迁移过来的生硬功能
3. **突出差异**：强化“算力预约”“订单投标”等核心卖点
4. **适度超前**：保留扩展能力，但不在MVP阶段实现


## 二、建议删除/简化的功能（6项）

### 2.1 可直接删除的功能

#### 1. 挂失补办功能
- **当前状态**：成员可自助挂失，后台一键补办
- **删除理由**：此功能源于“读者证”场景，OPC成员不存在“证件丢失”问题
- **替代方案**：提供“手机号验证码找回密码”即可
- **影响范围**：后台成员管理中的补办按钮、前台“挂失申请”页面

#### 2. 回收站与彻底删除功能
- **当前状态**：删除→回收站→彻底删除，三态流程
- **删除理由**：社区官网运营场景简单，三态流程过度设计
- **替代方案**：保留软删除（标记删除，前台不可见），后台提供“恢复”和“永久删除”两个操作按钮
- **影响范围**：后台服务管理/成员管理中的回收站页面及相关接口

#### 3. 公告系统及“逾期催办公告”定时任务
- **当前状态**：定时任务自动生成催办公告，完成时自动回收
- **删除理由**：社区运营中发布“催办通知”场景极少，且逻辑复杂
- **替代方案**：改用邮件通知（已实现）
- **影响范围**：Quartz定时任务中与公告相关的3个任务

#### 4. 数据快照自动同步 GitHub（git hooks）
- **当前状态**：每次`git commit`自动导出数据库业务数据为`data_snapshot.sql`
- **删除理由**：多人协作时有用，但官网项目数据结构变更频率极低
- **替代方案**：保留`scripts/export-data.bat`手动导出脚本，移除`.githooks/pre-commit`自动触发
- **影响范围**：`.githooks/pre-commit`文件

### 2.2 可简化/后置的功能

#### 5. Excel 批量导入与导出
- **当前状态**：后台可批量导入导出服务/成员数据
- **简化方案**：初期运营数据量小，手动添加足够
- **实施建议**：后置到二期（入驻OPC超过50家后开发）
- **影响范围**：后台服务管理/成员管理中的导入导出按钮及接口

#### 6. 复杂角色权限分级
- **当前状态**：多角色（服务/成员/运营等）+ 测试账号，RBAC完整落地
- **简化方案**：保留若依框架RBAC能力，但只预置“超级管理员”和“内容编辑”两个角色
- **实施建议**：其他角色在需要时再动态添加
- **影响范围**：系统管理中的角色管理预置数据


## 三、建议新增的功能（7项）

### 3.1 🔴 P0级别（MVP必须）

#### 1. 首页运营统计数字（动态数据）
- **功能描述**：官网首页展示动态更新的关键数据指标
- **建议数据项**：
  - 已入驻OPC数量
  - 已上线服务/活动总数
  - 政策文件总量
  - 合作企业/机构数
- **实现方式**：后台定时统计，提供API接口供前台调用
- **技术估算**：0.5人日
- **参考代码**：可利用若依框架现有的`Redis缓存+定时任务`机制，新增一个统计Service，首页通过Ajax异步加载。

#### 2. 算力资源预约系统 ★核心卖点
- **功能描述**：将宣传中的“70B以内大模型一体机免费试用”线上化
- **数据模型**：
  - `compute_resource`：资源清单（名称、型号、规格、总数量、可用数量、位置）
  - `compute_reservation`：预约记录（资源ID、申请人ID、用途描述、预约日期、时段、审批状态）
- **前台功能**：
  - 展示可用算力资源列表
  - 登录后可提交预约申请（选择资源、日期、填写用途）
  - 查看个人预约记录与审批状态
- **后台功能**：
  - 资源清单管理（增删改查、上下架）
  - 预约审批（通过/拒绝/排期）
  - 预约记录查看与导出
- **技术估算**：3-4人日
- **实现建议**：该功能涉及一个新的数据实体，建议先通过若依代码生成器生成基础CRUD模块，再添加预约审批状态流转的业务逻辑。

#### 3. 订单/项目发布与投标系统 ★核心卖点
- **功能描述**：将“文旅推广、政务科普等领域文创订单”线上化分发
- **数据模型**：
  - `project_order`：订单项目（标题、需求描述、预算、截止日期、状态）
  - `order_bid`：投标记录（订单ID、OPC成员ID、投标方案、报价、投标时间、状态）
- **前台功能**：
  - “机会列表”页面（登录后可见）
  - 点击查看订单详情
  - 在线提交投标方案
  - 查看个人投标记录
- **后台功能**：
  - 订单发布（创建/编辑/删除）
  - 投标管理（查看投标列表、标记中标/落选）
- **技术估算**：3-4人日
- **实现建议**：延续现有服务/报名的设计模式——`project_order`相当于“服务”、`order_bid`相当于“报名”，可复用现有代码结构。核心接口`/order/list`和`/order/detail`在前台公开，`/order/bid`需登录鉴权。

### 3.2 🟡 P1级别（上线后快速迭代）

#### 4. 政策智能匹配（规则引擎版）
- **功能描述**：访客填写基础信息，系统自动推荐适合的扶持政策
- **数据模型**：
  - `policy`：政策表（已有）
  - `policy_rule`：匹配规则（行业、团队规模、阶段 → 政策ID）
- **前台功能**：
  - “政策匹配”入口（按钮或独立页面）
  - 表单（行业下拉、团队规模、当前阶段、是否已注册公司）
  - 提交后展示匹配的政策列表
- **后台功能**：
  - 规则配置（增删改查）
- **技术估算**：2人日
- **实现建议**：MVP版本用简单规则引擎（if-else）实现，不需要接入真实AI。政策匹配结果本身已是差异化亮点。`policy_rule`表设计为多对多，即一个政策可匹配多种行业，一个规则也可对应多个政策。

#### 5. 线上讨论区（“游民茶馆”）
- **功能描述**：为OPC提供简单的线上交流空间
- **数据模型**：
  - `forum_post`：帖子（标题、内容、作者ID、发布时间、回复数、状态）
  - `forum_reply`：回复（内容、作者ID、帖子ID、发布时间）
- **前台功能**：
  - 帖子列表（登录后可见）
  - 发帖/回帖
  - 个人帖子管理
- **后台功能**：
  - 帖子审核（通过/删除/置顶）
  - 敏感词过滤（可选）
- **技术估算**：2-3人日
- **实现建议**：对若依框架来说，论坛功能几乎不需新增接口——发帖/回帖/列表查询/审核，与现有CMS文章管理的逻辑完全一致，只是数据结构从“文章分类”变为“帖子+回复”。可以优先复用代码生成器生成`forum_post`和`forum_reply`两张表的CRUD，再在后台添加帖子管理的独立菜单。

### 3.3 🟢 P2级别（社区成熟后开发）

#### 6. 外部服务集成（OPC工具箱）
- **功能描述**：汇集对OPC有用的外部工具/服务链接
- **数据模型**：
  - `external_tool`：工具（名称、描述、图标、URL、分类）
- **前台功能**：
  - “OPC工具箱”页面
  - 按分类筛选
  - 点击跳转外部链接
- **后台功能**：
  - 工具管理（增删改查、分类维护）
- **技术估算**：1人日

#### 7. 在线支付（可选）
- **功能描述**：B类入驻租金在线支付
- **实现方式**：对接微信支付/支付宝（企业账户）
- **技术估算**：3-4人日
- **前置条件**：需企业资质申请支付商户号

## 九、总结

| 维度 | 当前 | 调整后 |
|------|------|--------|
| **定位** | 业务中台+官网混合 | 聚焦官网+社区服务 |
| **前台页面** | 12页 | 12页（调整内容） |
| **后台菜单** | 约20个 | 约15个（精简） |
| **数据表** | 业务相关约10张 | 增至约14张（新增4张） |
| **定时任务** | 4个 | 1个 |
| **功能模块** | 约25项 | 约22项（删6增7，净增1项） |
| **代码量** | 约减少10% | 更聚焦、更轻量 |

**核心变化**：
- 砍掉约30%的“内部管理系统”冗余功能
- 新增约20%的“社区服务”核心功能
- MVP版本功能净增约1项，但结构更清晰、定位更准确

## 0. 项目一句话

数智游民创新工场官网 = 若依 RuoYi-Vue 3.9.2 二次开发：**纯静态官网前台（12 页）+ Vue 后台管理 + Java 业务 API**；原图书系统改造为「服务/成员/报名」体系（代码命名保留 book/reader/borrow，见下）。

## 3. 红线清单（历史事故与约定，违反即出 bug）

1. **前端登录/注册参数名**：登录用 `account`（证号/手机号/邮箱）+ `password`；注册用 `readerName`（不是 `name`——Spring 按参数名绑定，写错登录/注册永远失败）。
2. **前台会话凭证**：必须走 `apiFetch()`（自动带 `X-Session-Token` 头），**禁止裸 `fetch`**——contest.html 曾因裸 fetch 无凭证导致「报名必败」（三轮审查才抓出来）。
3. **前台 XSS 防线**：所有库数据插值前过 `esc()`；文章正文用 `textContent` + `https?://` 链接白名单渲染，**禁止 innerHTML 直插正文**。
4. **公共脚本单一来源**：认证/工具/导航逻辑只在 `public/js/site.js`，12 页共用。**勿向页面复制粘贴**；页面私有逻辑用 `window.AUTH_AFTER_LOGIN/LOGOUT` 钩子。
5. **数据库升级脚本三链同步**：`docker/mysql-init.sh`（新库）、`docker/mysql-upgrade.sh`（旧库，权威清单）、`scripts/start-all.bat`（Windows 旧库）——**新增 upgrade 脚本必须三处同步**，否则 Windows 老库升级后登录/列表直接 500（曾缺 auth 脚本）。
6. **后端改动必须重新打包重启**：`mvn -pl ruoyi-admin -am package -DskipTests` + 重启 java。旧 jar + 新页面 = 版本错位（R1 事故：所有会话操作报「登录已失效」）。
7. **dist 不入 git**：部署/预览前 `npm run build:prod` 重建；Docker 用 `docker compose build` 或删旧镜像，否则跑旧站。
8. **SQL 导入必带字符集**：`--default-character-set=utf8mb4`，否则 Windows 终端 GBK 把中文读坏入库（菜单乱码 → getParentId 空指针）。
9. **CMS 发布权限**：草稿/下线→已发布需 `system:cms:publish`（后端 `checkPublishPerm` 强制 + 前端 radio 按权限显示）；仅 edit 权限**不能**发布。
10. **会话时长**：前台 14 天滑动续期（sys_config `reader.session.minutes`）；密码重置/代设密后全端吊销。**测试/文档勿再写 30 分钟**。
11. **频控 IP 信任链**：IP 频控 key 依赖 `X-Forwarded-For` 末段——前提是 nginx 追加式 XFF + 8080 不直连公网，**两者必须同时成立**，否则可伪造 IP 绕过。
12. **回收站两态**：软删除 `del_flag='2'` + 恢复/彻底删除；三态快照死代码已删，勿恢复。
13. **editor 角色**：菜单/按钮授权在 `sql/upgrade_20260825_05_editor_fix.sql`（新目录四分组）；改菜单结构必须同步该脚本 + role_init.sql。
14. **commit 时 data_snapshot.sql 自动变化是正常现象**（pre-commit 钩子导出业务快照，已排除 PII 两表），直接提交即可。
15. **CI 测试**：`mvn -B test -pl ruoyi-system -am` 必须全绿（当前 114/114）；改动报错文案/接口签名时同步更新测试（曾因认证改造忘更测试，CI 红多日）。

## 4. 高频问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录后操作提示「登录已失效」 | 后端旧 jar（版本错位） | 重新打包重启后端 |
| 页面是旧版 | dist 未重建 / 旧镜像 | `npm run build:prod`；`docker compose build` |
| 邮件发不出 | 授权码错 / SMTP 未开 | 后台「系统设置→邮件通知」测试发送；QQ 邮箱开启 SMTP |
| 后台快捷入口 404 | 路由写死旧菜单路径 | 新路径 `/content/book`、`/member/borrow|purchase|reader` |
| 报名提示「名额不足」 | 正常业务拦截 | 服务名额 0 时前台只留候补 |

## 5. Push 前自检清单

1. `mvn -B test -pl ruoyi-system -am` 全绿（114/114）
2. 改过的 HTML 内联脚本 `node --check` / `new Function()` 语法通过
3. 全仓 grep 无新引入的旧术语（图书/读者/借书）、无 `admin123`、无真实密钥/手机号
4. 新增 upgrade 脚本已同步三链；README/部署指南升级清单同步
5. 后端改动已重新打包验证（8080 起得来、公开接口 200）
6. 涉及数据库结构 → 本地库执行过对应 upgrade 脚本

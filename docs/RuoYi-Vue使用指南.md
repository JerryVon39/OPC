## 1. 系统是什么

### 1.1 大白话定义

**若依是一套"现成的公司内部管理系统"。**

你平时买东西用的是面向顾客的**前台**（淘宝、京东的页面）；而商家自己管理商品、员工、订单用的，是**后台**。若依就是帮你把后台系统**最通用、每家公司都要用的部分**全部做好：

| 已做好的（免费送） | 需要你自己做的（业务部分） |
|---|---|
| 登录、账号、密码管理 | 电商 → 商品管理、订单管理 |
| 员工名单、部门、岗位、角色权限 | 学校 → 学生管理、课程管理 |
| 公告、操作日志、登录日志 | 医院 → 挂号管理、病历管理 |
| 定时任务、文件上传、Excel 导入导出 | 你自己的业务表 |
| 数据字典、参数配置、各种监控 | （用代码生成器快速完成！） |

**核心价值**：90% 的公司系统功能长得一样（登录、管人、管权限、管数据）。若依把这些做好，你只需要专注自己业务那 10%，而且连这 10% 都有"代码生成器"自动帮你造。

### 1.2 技术选型（每个名词一句话解释）

登录后首页的"技术选型"栏目列出了框架的家底：

| 技术 | 一句话解释 |
|---|---|
| Spring Boot | Java 后端的"地基框架"，负责启动 Web 服务 |
| Spring Security | 安全防护，负责登录验证和权限拦截 |
| JWT | 登录凭证（token），像一张"带签名的通行证" |
| MyBatis | 操作数据库的工具（写 SQL 的地方） |
| Druid | 数据库连接池 + 监控（看到实时 SQL 就靠它） |
| Redis | 高速缓存（登录会话、字典、参数都存这里） |
| Quartz | 定时任务调度器 |
| Vue 2 | 前端框架（页面是怎么渲染出来的） |
| Element UI | 现成的界面组件库（表格、按钮、弹窗都来自它） |
| Axios | 前端向后端发请求的工具 |

> 💡 你不需要现在全部掌握。知道"它们是干什么的"即可，用到时再深入。

## 2. 日常启动与停止

### 2.1 启动（每次开机后）

系统由 4 个部分组成，**启动顺序：Redis → MySQL → 后端 → 前端**。

| 步骤 | 操作 | 说明 |
|---|---|---|
| 1 | 双击 **`C:\Users\1\tools\start-all.bat`** | 一键脚本，自动完成下面所有事 |
| 2 | 等约 30~40 秒 | 后端启动最慢（要加载所有模块） |
| 3 | 打开浏览器访问 http://localhost:8081 | 看到登录页 = 成功 |
| 4 | 登录 admin / admin123 | 进入系统首页 |

脚本自动完成的动作：
```
清理 4 个端口的旧进程 → 启动 Redis(6379)
→ 启动 MySQL(3306) → 循环检测 MySQL 就绪（最多等 40 秒）
→ 启动后端(8080) → 启动前端(8081)
```

**如何判断启动成功**（任选一种）：
- 浏览器打开 http://localhost:8081 能看到登录页
- 任务管理器能看到 java.exe、node.exe、mysqld.exe、redis-server.exe 四个进程
- 命令行执行 `netstat -ano | findstr "8080"` 能看到 LISTENING

### 2.2 停止

| 方式 | 操作 | 适用场景 |
|---|---|---|
| 关窗口 | 直接关掉 4 个启动窗口 | 平时用这个最方便 |
| 停止脚本 | 双击 `C:\Users\1\tools\stop-all.bat` | 窗口不见了 / 服务是别人启动的 |
| 任务管理器 | Ctrl+Shift+Esc → 结束 java.exe / node.exe / mysqld.exe / redis-server.exe | 前两种失灵时 |

> ⚠️ `taskkill /F /IM java.exe` 这类命令会杀掉**电脑上所有**同名程序，如果还有其他 Java 程序在跑，别用。

### 2.3 端口对照表

| 服务 | 端口 | 密码/说明 |
|---|---|---|
| 前端页面 | 8081 | 浏览器访问的入口（本机无管理员权限，不能用默认的 80） |
| 后端接口 | 8080 | 前端把请求转发到这里 |
| MySQL | 3306 | 账号 root，密码 password |
| Redis | 6379 | 无密码 |

### 2.4 启动常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 双击脚本没反应/窗口闪退 | 脚本被编辑器改过编码 | 重新用 Python 转 GBK，或找我 |
| 后端窗口报"端口被占用" | 上次的服务没停干净 | 脚本第 0 步会自动清理；或先跑 stop-all.bat |
| 后端窗口报"Connection refused" | MySQL 没起来 | 重跑脚本（已带就绪检测）；确认 3306 在监听 |
| 页面打不开 | 前端没起来 | 看 8081 是否监听，等 npm 编译完成（首次较慢） |

## 4. 系统管理（人事行政部）

### 4.1 用户管理 —— 员工花名册

**页面长什么样**（这是所有业务列表页的**标准模板**，一定要看懂）：

```
┌─ 左侧：部门树 ────────┬─ 搜索区 ──────────────────────────┐
│ 若依科技              │  用户名称[ ] 手机号码[ ] 状态[ ]   │
│ ├─ 深圳总公司          │  [搜索] [重置]                    │
│ │  ├─ 研发部门 ←admin │  ──────────────────────────────── │
│ │  ├─ 市场部门          │  工具栏：[新增][修改][删除][导入][导出] │
│ │  ├─ 测试部门 ←ry     │  ──────────────────────────────── │
│ │  └─ 财务/运维部门     │  表格：编号|用户名称|部门|状态|创建时间|操作 │
│ └─ 长沙分公司          │  1  admin  研发部门  ●启用  ...    │
│                        │  ──────────────────────────────── │
│                        │  分页：共 2 条  ◀ 1 ▶             │
└────────────────────────┴─────────────────────────────────┘
```

**各部分含义**：

| 区域 | 作用 | 新手提示 |
|---|---|---|
| 左侧部门树 | 按部门过滤右侧列表 | 点"研发部门"只看研发的人 |
| 搜索区 | 组合条件查询 | 时间范围搜索很常用 |
| 工具栏按钮 | 批量操作入口 | **每个按钮背后都有权限控制**，没权限的人看不到按钮 |
| 表格 | 数据展示 | 点行首复选框可多选，配合批量删除 |
| 分页 | 数据多时翻页 | 每页条数可调（10/20/50 条） |

**用户有哪些字段**：

| 字段 | 说明 |
|---|---|
| 用户名称 | 登录账号，唯一，创建后不可改 |
| 用户昵称 | 显示名，可随时改 |
| 归属部门 | 这个人是哪个部门的 |
| 手机号码 / 邮箱 | 联系方式，可做唯一校验 |
| 用户性别 | 字典管理里的"用户性别"类型（男/女/未知） |
| 状态 | 正常 / 停用（停用 = 立即无法登录） |
| 岗位 | 职责标签（项目经理、普通员工…） |
| 角色 | **权限套餐**——决定能看到哪些菜单（核心） |
| 备注 | 自由填写 |

🖱️ **练习：新增一个测试用户（10 分钟，感受权限）**
1. 用户管理 → 新增
2. 填写：用户名称 `test`、昵称 `测试员`、归属部门"测试部门"、密码 `admin123`
3. 角色选"**普通角色**"（不要选超级管理员！）
4. 保存 → 退出登录 → 用 test/admin123 登录
5. **对比菜单**：你会看到"系统工具"等菜单不见了——因为普通角色没有勾这些权限
6. 回到 admin，删除这个测试用户

> 💡 超级管理员角色（admin）不能被分配给新用户，这是保护机制。

### 4.2 角色管理 —— 权限包（核心！）

**角色 = 权限套餐**。给角色勾选菜单权限，凡是挂了这个角色的用户，自动获得套餐内所有权限。

**角色列表字段**：角色名称、权限字符（如 `common`）、显示顺序、状态、创建时间。

**修改角色的两个页签**（重点）：

**① 菜单权限页签**——勾选这个角色能看到哪些功能：
```
┌─ 分配权限 ─────────────────────────────┐
│ ☑ 系统管理                              │
│    ☑ 用户管理      ☑ 用户查询 ☑ 用户新增 │
│    ☑ 角色管理      ☑ 角色查询 ☑ 角色新增 │
│    ☐ 系统监控      ← 不勾 = 看不到+用不了 │
│    ☑ 系统工具      ☑ 表单构建 ☐ 代码生成 │
│ 展开/折叠 全选/全不选 父子联动           │
└────────────────────────────────────────┘
```
- 勾选父节点会自动勾选子节点（父子联动）
- **菜单（页面）级别**控制"能不能进入这个页面"
- **按钮级别**控制"页面里的按钮显不显示"

**② 数据权限页签**——控制"能看哪些部门的数据"：

| 数据权限 | 含义 | 例子 |
|---|---|---|
| 全部数据权限 | 谁的数据都能看 | 老板 |
| 自定数据权限 | 手动指定部门 | 指定只让看深圳分公司的 |
| 本部门数据权限 | 只看自己部门的 | 部门经理 |
| 本部门及以下数据权限 | 部门+子部门 | 分公司老总 |
| 仅本人数据权限 | 只看自己创建的 | 普通员工 |

🖱️ **练习：体验权限变化（10 分钟）**
1. 角色管理 → "普通角色" → 修改 → 菜单权限
2. 取消勾选"系统监控"，保存
3. 用 ry 账号（密码 admin123）登录 → "系统监控"菜单消失了
4. 改回来，再刷新 ry 的页面 → 菜单回来了

> ⚠️ 修改角色权限后，**已登录用户需要重新登录或刷新**才能看到变化（权限在登录时加载）。

### 4.3 菜单管理 —— 功能点清单

菜单表是系统的"功能总目录"，同时承担三件事：**页面导航 + 权限控制 + 按钮显隐**。

**三种类型（列表的 M/C/F 标签）**：

| 类型 | 字母 | 作用 | 例子 |
|---|---|---|---|
| 目录 | M | 菜单分组（不打开页面） | "系统管理" |
| 菜单 | C | 一个实际页面 | "用户管理" |
| 按钮 | F | 页面上的操作按钮 | "用户新增" |

**菜单的关键字段**：

| 字段 | 含义 | 新手提示 |
|---|---|---|
| 菜单名称 | 界面显示的名字 | |
| 路由地址 | 页面路径 | 前端跳转用 |
| 权限字符 | 如 `system:user:add` | **后端接口校验 + 前端按钮显隐都靠它** |
| 图标 | 菜单前面的小图标 | 可搜索图标 |
| 显示状态 | 显示/隐藏 | 隐藏的菜单页面还能直接访问（权限仍在） |
| 菜单状态 | 正常/停用 | 停用后角色分配时不可勾选 |
| 排序 | 数字越小越靠前 | |

🖱️ **练习：看一个按钮的权限**
1. 菜单管理 → 搜索"用户" → 找到"用户新增"（类型 F）
2. 记住它的权限字符 `system:user:add`
3. 去角色管理 → 普通角色 → 菜单权限 → 取消勾选它 → 用 ry 登录 → 用户管理页面里的"新增"按钮消失了

### 4.4 部门管理 —— 组织架构图

- 树形结构：公司 → 分公司 → 部门（最多可很多级）
- 字段：部门名称、负责人、联系电话、邮箱、排序、状态
- 用户管理左侧的部门树、角色的数据权限，都依赖这张表
- 删除部门前必须先把部门里的人员移走

🖱️ **练习**：新增一个部门"图书馆"，挂到"研发部门"下面（实战课会用到组织结构）。

### 4.5 岗位管理 —— 职位定义

| 对比项 | 岗位（post） | 角色（role） |
|---|---|---|
| 本质 | 职责标签 | 权限套餐 |
| 例子 | 项目经理、普通员工 | 管理员、普通角色 |
| 影响权限吗 | 不直接影响 | 决定能看到什么 |

一个用户可以挂多个岗位和多个角色。

### 4.6 字典管理 —— 统一术语表（很实用）

**解决什么问题**：假如系统里 10 个页面都有"性别"下拉框，每个页面都写一遍选项？不用——字典表里配一次，所有页面自动读取。

**页面结构**：
- 左侧：**字典类型**列表（如 `sys_user_sex` 用户性别）
- 右侧：该类型下的**字典数据**（男 / 女 / 未知）

**字典数据的字段**：
| 字段 | 说明 |
|---|---|
| 字典标签 | 显示的文字（男） |
| 字典键值 | 存进数据库的值（0） |
| 显示排序 | 下拉框里的顺序 |
| 回显样式 | 在列表里显示成标签/警告样式等 |

🖱️ **练习：建一个"图书分类"字典（实战课素材，5 分钟）**
1. 字典管理 → 左侧"新增" → 字典名称"图书分类"、字典类型 `book_type` → 确定
2. 右侧"新增"：
   - 标签"文学"、键值 `1`、回显样式"primary"
   - 标签"科技"、键值 `2`
   - 标签"历史"、键值 `3`
3. 完成后可在左侧点击 `book_type` 查看

### 4.7 参数设置 —— 系统开关

键值对形式的配置中心。**存在数据库里**（改配置不用重启、不用动代码）。

| 参数键 | 含义 | 本机当前值 |
|---|---|---|
| `sys.account.captchaEnabled` | 登录验证码开关 | false（已关） |
| `sys.user.initPassword` | 新用户初始密码 | 123456 |
| `sys.user.passwordChangePeriod` | 强制改密周期（天） | 0=不强制 |
| `sys.login.passwordErrorCount` | 密码错误锁定阈值 | 5 |
| `sys.login.passwordLockTime` | 锁定时间（分钟） | 10 |

🖱️ **练习**：把验证码开关改回 true → 清 Redis 缓存（或重启后端）→ 重新登录，看看验证码回来了。再改回 false。

> 💡 为什么改完要清缓存？因为参数会缓存到 Redis 加速读取，改库后缓存还是旧值。

### 4.9 日志管理 —— 监控录像

| 对比 | 操作日志 | 登录日志 |

## 5. 系统监控（体检中心）

### 5.1 在线用户 —— 谁登录着

- 展示所有有效登录会话（存在 Redis 里）
- 字段：会话编号、登录名称、部门、主机（IP）、登录时间
- 操作：**强退** = 立即删除该会话，对方下一次操作就被踢出登录

🖱️ **练习**：开两个浏览器窗口（一个普通窗口一个无痕窗口）分别登录两个账号 → 在在线用户里强退其中一个 → 回到那个窗口随便点点，会被弹回登录页。

### 5.2 定时任务 —— Quartz 调度

- 任务列表：任务名称、调用目标（如 `ryTask.ryNoParams`）、cron 表达式、状态
- 操作：执行一次 / 暂停 / 恢复 / 修改 / 日志
- **cron 表达式**：表示"什么时候执行"的密码（如 `0/10 * * * * ?` = 每 10 秒一次），页面自带**在线生成器**（点 cron 输入框旁的工具图标）

🖱️ **练习**：找一个内置任务，点"执行一次"，然后看"调度日志"确认执行结果。

### 5.3 数据监控 —— Druid 连接池

- 登录：**ruoyi / 123456**（这是 Druid 自己的账号，不是系统账号）
- 能看到：数据源状态、活跃连接数、SQL 执行列表、慢查询
- 新手用法：**开发时排查"哪个接口执行了什么 SQL"**特别好用

### 5.4 服务监控 —— 电脑状态汇报

- 显示本机 CPU 使用率、内存、磁盘、JVM 信息（Java 虚拟机）、服务器信息
- 用途：发现系统变慢时，先看是不是机器资源不够

### 5.5 缓存监控 —— Redis 状态

- 基本信息：Redis 版本、运行模式、端口、客户端数、使用内存、Key 数量
- 命令统计：哪个命令被调用了多少次（饼图）
- 内存信息：内存使用情况

### 5.6 缓存列表 —— Redis 里的键

- 按缓存类型查看键列表（登录会话 / 配置 / 字典 / 验证码 / 防重提交…）
- **能干什么**：
  - `login_tokens:*` 开头的键 = 登录会话 → 删除一个 = 把那个人踢下线
  - `sys_dict:*` = 字典缓存 → 改完字典不生效时，在这里删掉它（等于刷新）
  - `sys_config:*` = 参数缓存

> ⚠️ "清空缓存"会删除**全部** Redis 数据（包括所有在线会话），操作前想清楚。

**它解决什么问题**：每个业务模块（图书、学生、商品…）都要写"增删改查"——查询列表、新增表单、修改表单、删除、导出 Excel、权限控制、分页……这些代码 90% 长得一样。代码生成器**一键产出全套**。

```
      ↓
④ 点【生成代码】→ 自动产出 7 个文件
   后端 4 个：Domain实体 / Mapper / Service+实现 / Controller
   前端 3 个：列表页 index.vue / 表单 / api.js
      ↓
⑤ 把文件放进项目对应目录（菜单管理里也可直接"生成到本地"）
      ↓
⑥ 菜单管理 → 新增菜单：
   菜单名称（图书管理）、路由地址、权限字符（system:book:list）
      ↓
⑦ 刷新页面 → 你的业务模块上线！自带增删改查/分页/搜索/导出/权限
```

**生成出的页面自带什么**（理解它的价值）：
- 列表页：搜索区 + 表格 + 分页 + 新增/修改/删除/导出按钮
- 表单：字段校验（必填、长度）、下拉字典自动读取

> 💡 表名和字段命名有约定：表名如 `book`，字段用下划线 `book_name`，主键 `book_id`。生成器会自动把 `book_name` 转成 Java 的 `bookName`。

## 8. 权限模型原理（RBAC）

**RBAC = Role-Based Access Control，基于角色的权限控制**。这是整个若依的灵魂，值得反复理解。

### 8.1 四张表的关系（公司类比）

```
                    ┌─────────────┐
                    │  sys_user    │ 员工花名册
                    │ （用户）     │
                    └──────┬──────┘
                           │ 属于（dept_id）
                    ┌──────▼──────┐
                    │  sys_dept    │ 组织架构
                    │ （部门）     │
                    └─────────────┘

   用户 ──拥有──▶ 角色（sys_role）
                     │
                     │ 勾选了（sys_role_menu 关联表）
                     ▼
                  菜单（sys_menu）＝ 功能点清单
                   ├─ 目录 M（分组）
                   ├─ 菜单 C（页面）
                   └─ 按钮 F（操作，带权限字符 system:user:add）
```

**一句话**：用户挂角色，角色勾菜单，菜单带权限字符。

### 8.2 权限怎么生效（完整链路）

以"删除用户"按钮为例，它经历四道检查：

```
① 登录时：后端查出 admin 的权限集合
   ["system:user:list", "system:user:add", "system:user:remove", ...]
      ↓ 存在 Redis，随每次请求校验
② 前端渲染：按钮上有权限指令
   "删除"按钮 → 检查权限集合有没有 system:user:remove
   → 没有 → 按钮不渲染（你看不到它）
      ↓
③ 你点删除 → 前端向后端发请求 → 带上 token
      ↓
④ 后端拦截：接口上有 @PreAuthorize 注解
   → 校验 token 里的权限 → 没有 → 返回 403
   → 有 → 执行删除
```

**关键结论**：
- 前端藏按钮 = 体验层（防止误点）
- **后端拦接口 = 真正的防线**（即使绕过前端直接调接口也会被拦）
- admin 是超级管理员，直接放行一切，不受勾选限制

### 8.3 权限的两种控制

| 控制类型 | 控制什么 | 在哪配 |
|---|---|---|
| 功能权限 | 能不能看页面/按钮 | 角色 → 菜单权限 |
| 数据权限 | 能看哪些部门的数据 | 角色 → 数据权限 |

## 10. 常见问题 FAQ

| 问题 | 原因 | 解决 |
|---|---|---|
| 页面提示"网络错误/连接失败" | 服务没启动 | 双击 start-all.bat，等 30 秒 |
| 登录一直失败 | 密码错/账号停用/被锁定 | 去登录日志看失败原因；密码错误 5 次锁 10 分钟 |
| 改完字典/参数不生效 | 有 Redis 缓存 | 缓存列表里删对应键，或重启后端，或 FLUSHALL |
| 缓存监控报 "cannot read redis info" | Redis 装在含 `\u` 的路径触发 Java 解析 bug | 已修复（Redis 在 C:\Redis）；以后别装 user 目录 |
| 修改角色权限后用户没变化 | 权限登录时加载 | 让用户重新登录 |
| 停用用户还在系统里 | 停用对已登录会话不立即生效 | 在线用户里强退 |
| 前端 npm 报 OpenSSL 错误 | Node 版本太新 | 装 Node 16/18 LTS |
| 80 端口打不开 | 无管理员权限 | 用 8081（脚本已配置） |
| 菜单/页面 404 | 菜单的路由地址配置错误 | 检查菜单管理里的路由地址和前端页面路径一致 |
| 删不掉部门 | 部门下还有用户 | 先把用户移走或删除 |
| 忘记 admin 密码 | — | 数据库执行 `UPDATE sys_user SET password='...' WHERE user_name='admin'`（BCrypt 加密，需生成） |

## 13. 若依与实际软件开发

### 13.1 它不是"另一个软件"，它就是你的软件

**最核心的认知**：若依不是需要"对接"的外部系统，它是**你的软件的骨架**——业务代码长在它身体里，最后编译成**同一个程序**（一个 jar、一个网站）。

以 Book 模块为例，它就是这么"连接"进若依的：

| 连接方式 | 发生了什么 | 结果 |
|---|---|---|
| Book.java 放进它的包目录 | Spring 组件扫描自动发现、注册 | 接口自动可用 |
| index.vue 放进 views 目录 | 菜单表的路由指向它 | 页面自动出现 |

### 13.2 它在实际开发中的角色

```
一个实际系统 = 若依骨架 + 你的业务模块
                 │            │
                 │            ├─ 图书管理、订单、报表（你的代码，30~50%）
                 │            └─ 你的业务逻辑、计算、规则、第三方对接

```

**角色定位**：基础设施 + 管理后台 + 权限中心 + 审计中心，四个角色合一。你雇了个"物业公司"管公共设施，你只管自己房间。

### 13.3 与其他代码/文件的三种"连接"

1. **后端代码**：放进 ruoyi-system 模块包结构 → Spring 组件扫描自动发现
2. **前端文件**：放进 ruoyi-ui/src/views/ → 菜单表的"组件路径"字段指到它 → 页面出现（**菜单表 = 前后端的"接线图"**）
3. **外部系统**：若依后端暴露标准 HTTP 接口（GET /system/book/list）→ **任何程序都能调用**：小程序、App、第三方系统。前端页面只是接口的众多调用者之一

> 💡 一套后台，多端使用：管理后台 + 小程序 + App 共用同一套接口和数据。

**终极答案**：若依 = **"企业级后台系统的地基 + 公共设施包"**。你写业务，它管一切"每家公司都要有的东西"。

## 14. 核心架构：前后端分离与"一体两面"

### 14.1 数据流：前端永远不直接碰数据库

```
前端（管理后台 / 书店前台 / 小程序）
        │ 只能通过 HTTP 接口
        ▼
后端（若依）← 权限校验、业务逻辑都在这道墙里
        │ 后端自己连数据库
        ▼
数据库
```

**为什么前端不能直接连数据库**：如果前端能直连数据库，任何人都能绕过权限直接改数据（比如顾客把自己订单改成"已支付"）。正因为**所有人都只能走接口这一扇门**，后端才能在门上做权限校验、日志审计、限流防攻击——这是整个权限体系能成立的前提。

### 14.2 一体两面

| 面 | 连接方式 | 使用人群 |
|---|---|---|
| **接口面**（朝外） | HTTP 接口（GET /system/book/list） | 小程序、App、前台网站 |
| **界面面**（朝内） | 管理后台网页 | 员工（admin 等账号） |

两面对接**同一套接口和同一个数据库**——就像餐厅的厨房（出菜给前台）和办公室（员工管账）共用同一个食材仓库。

### 14.3 若依的准确定义（一句话）

> 若依 = 一套自带完整管理后台的企业级后端框架。对外提供 HTTP 接口（小程序/App/网站都能连），对内提供管理界面（员工管数据用），核心能力是业务数据管理 + 权限控制 + 日志审计 + 系统监控。

## 16. 若依 vs 微信云开发

**相似点**：两者都让开发者"不用自己搭后端基础设施"（数据库、鉴权、接口都有现成的）。

**本质区别**：

| 维度 | 微信云开发 | 若依 |
|---|---|---|
| 本质 | 云平台托管服务（PaaS，腾讯的服务器） | 开源后端框架（装在自己服务器） |
| 服务器/数据库 | 腾讯提供，按量付费 | 自己买服务器、装 MySQL/Redis |
| 鉴权 | 微信免鉴权（openid） | 自建账号体系 + JWT |
| 管理后台 | ❌ 没有 | ✅ 自带完整后台 |
| 权限模型 | 简单（云函数级） | 企业级 RBAC（按钮级） |
| 日志审计 | ❌ 无 | ✅ 完整操作日志 |
| 掌控度 | 低（平台限制） | 高（全部源码在手） |
| 适用 | 个人项目、快速原型、微信生态 | 企业级业务系统 |

**类比**：云开发 = 租精装共享办公室（拎包入住，按天付费）；若依 = 买毛坯房自己装修（一次买断，水电物业自己管）。

**选型建议**：个人小程序/作业/快速验证 → 云开发；企业小程序（要后台管理、多员工、审计合规）→ 自建后端 + 小程序前端。

## 17. 若依的隐藏机制与本机定制记录

### 17.1 逻辑删除（del_flag）

- 若依的"删除"是**逻辑删除**：记录还在数据库里，只是 `del_flag` 标记为 '2'（正常为 '0'），列表查询自动过滤
- 恢复方法：`UPDATE sys_user SET del_flag='0' WHERE user_id=2;`（同时需恢复用户-角色关联表）
- ⚠️ 本机踩过：ry 用户曾因删除练习"消失"，就是被逻辑删除了

### 17.2 缓存机制（改数据不生效的常见原因）

| 数据 | 缓存位置 | 修改后如何生效 |
|---|---|---|
| 字典 | Redis（sys_dict:*） | 清缓存或重启后端 |
| 参数 | Redis（sys_config:*） | 清缓存或重启后端 |
| 用户信息 | Redis（login_tokens:*） | 重新登录 |
| 部门/岗位 | 无缓存 | 直接生效 |

常用命令：`redis-cli FLUSHALL`（清空全部，最粗暴但有效）

## 18. 购书系统（购物车 → 订单 → 库存联动）

### 18.1 数据流全景

```
顾客前台（shop.html）            后端（匿名接口）              数据库
─────────────────────────────────────────────────────────────────
加购物车 → localStorage(wswCart)     —                          购物车（浏览器本地）
结算     → POST /system/order/create → 校验证号/图书/库存 → 创建订单 + 库存-1
我的订单 → GET  /system/order/queryByCard → 按证号查订单列表
取消订单 → POST /system/order/cancelByCard → 证号归属校验 → 状态置取消 + 库存回补
后台管理 → /system/order/list + PUT → 完成/取消 + 库存回补
```

### 18.2 关键业务规则

| 规则 | 实现位置 |
|---|---|
| 下单校验：证号存在 / 读者未挂失 / 图书在架 / 库存充足 | `ShopOrderServiceImpl.createOrder` |
| 订单号格式：`WSW + 时间戳`（唯一） | `createOrder` |
| 下单 → 库存 -数量（与订单创建同事务） | `@Transactional` |
| 取消订单（后台或前台）→ 库存 +数量（防重复取消双倍回补） | `updateShopOrder` / `cancelByCard` |
| 订单状态：0 待处理 → 1 已完成 / 2 已取消 | `shop_order.status` |

### 18.3 购物车为什么存 bookId 而不是书名

早期版本购物车只存书名，结算时按书名反查图书。两个隐患：**同名书会下错单**、**改名后匹配不上**。改为直接存 `bookId` 后，结算按 ID 下单，准确且少一次查询。旧购物车数据（无 bookId）会自动清理。

## 20. 代码审查与修复记录（2026-08-13）

一次全面审查发现并修复的问题（按严重程度）：

### 严重
1. **封面上传保存不落库**：`BookMapper.xml` 的 insert/update 缺 cover/isbn/intro 三列 → 上传成功但刷新即丢。修复：补全三列写入。
2. **后台图书页被外部编辑器破坏**：封面功能丢失 + `handleBorrow(row)` 引用未定义变量 → 整体重写。

### 权限（任意登录用户可操作他人数据）
3. 借阅/订单后台接口全部缺 `@PreAuthorize` → 补齐权限注解 + 前端按钮 `v-hasPermi`。

### 逻辑漏洞
4. **逾期还能续借**：逾期状态是查询时动态算的（不落库），续借检查不到 → 改为直接比较应还日期与当前时间。
5. **取消订单不回滚库存**：库存越取消越少 → 取消时自动回补。
6. **前台封面 404**：封面是 `/profile/...` 相对路径，前台需加 `/dev-api` 代理前缀。

### 健壮性
7. 下单/借书/还书加 `@Transactional`（库存与记录同生共死）。
8. 挂失读者登录前台被拒；证号唯一约束 + 登记查重。
9. 催还公告当天去重；还书后自动回收/更新催还公告。
10. 前台详情弹窗与搜索不同步 → 改用当前列表取数。

## 23. 权限分级、差异化规则与数据一致性（2026-08-13 后补）

### 23.1 角色权限分级（RBAC 落地）

| 角色 | 账号 | 密码 | 可见范围 |
|---|---|---|---|
| 超级管理员 | admin | admin123 | 全部（含系统管理/监控/工具） |
| 图书管理员 | librarian | admin123 | 图书/读者/借阅/统计（无订单/系统管理） |
| 收银专员 | cashier | admin123 | 订单 + 借阅办理 + 图书读者查看 |
| 统计访客 | viewer | admin123 | 只看数据看板 + 借阅统计 |

初始化脚本：`sql/role_init.sql`（幂等）。权限配置入口：系统管理 → 角色管理（权限树勾选）→ 用户管理（分配角色）。

### 23.2 读者类型差异化借阅规则

| 规则 | 学生(1) | 教师(2) | 普通读者(3) |
|---|---|---|---|
| 借阅上限 | 5 本 | 10 本 | 3 本 |
| 借期 | 30 天 | 60 天 | 30 天 |

参数键：`book.borrow.maxCount.{student|teacher|normal}`、`book.borrow.days.{student|teacher|normal}`（后台参数设置可改，无类型参数时回退通用键 `book.borrow.maxCount`）。

### 23.3 数据一致性设计（快照 vs 实时）

| 数据 | 存储方式 | 修改名字后 | 删除读者/书后 |
|---|---|---|---|
| 借阅记录 | 快照（reader_name/card_no/book_name 落库，借书时写入） | 不变 | 历史完整 |
| 订单 | 快照（下单时写入） | 不变 | 历史完整 |
| 公告 | 纯文本 | 不变 | 历史完整 |
| 图书/读者当前信息 | 实时（主表） | — | — |

**设计原则**："凡涉及人的名字都是快照，凡当前状态都实时关联"。删除保护：未还借阅/待处理订单存在时禁止删除。

### 23.4 逾期罚款与订单收款（2026-08-13 后补）

**罚款闭环**：还书时逾期超免罚天数自动结算（`book.fine.perDay` 单价 / `book.fine.graceDays` 免罚天数，参数可配）→ 有未缴罚款的读者**冻结借书** → 后台借阅记录"罚款"列点**收款**清欠 → 看板显示欠费总额。

**订单状态流**：`0 待付款 → 3 已收款 → 1 已完成`；仅待付款可取消（取消回滚库存）。后台订单页"收款"按钮模拟线下收款/线上支付成功。

**挂失补办**：读者管理"补办"按钮 → 生成新证号 + 状态恢复（旧证号作废，历史快照保留）；前台导航"🪪 补办证号"也可自助申请（**姓名+登记手机号**校验，证号丢失也能补办），补办时历史借阅快照证号自动同步。

**我的信息**：前台登录后"我的借阅"弹窗底部可修改手机号（证号+姓名校验）。

**登录态优化**：登录后自动隐藏"读者登记"入口（登记过的读者无需再登记），退出登录恢复显示。

**响应式布局**：≤768px 手机版（多行导航/两列卡片）；769~1500px 中等窗口（导航自动多行，8 个功能按钮整齐排列不参差）；>1500px 单行。

**图书预约**：库存为 0 的在售书显示"📌 预约"（仅库存 0 可预约，有库存提示直接借）→ 同一本书多人预约先进先出 → 归还时自动将最早预约人状态置"可借"（前台绿色提示"请尽快到馆借阅"）→ 预约人借出后预约自动完成 → 预约中/可借可自助取消。**已借未还不可预约**（归还后可直接再借）。**超时机制**：可借状态超过 `book.reserve.expireDays`（默认 2 天）未借自动取消并通知下一位（每天 8 点任务）。演示数据：《白夜行》四状态链（教师可借/学生预约中/普通已完成/Jerry 已取消）。

**续借次数限制**：每本图书最多续借 `book.borrow.renewLimit`（默认 1）次，续借成功次数落库（renew_count），超限拒绝；前台"我的借阅"显示已续借次数并置灰按钮。

**BBCODE 富文本**：图书简介、公告内容支持轻量标记（`[b]`粗体 `[i]`斜体 `[u]`下划线 `[color=red]`红字 `[size=18]`字号 `[url=https://x]`链接 `[img]`图片 `[quote]`引用 `[code]`代码 `[center]`居中），后台图书表单有快捷工具栏（光标插入/颜色/链接/清除格式）；渲染前先 HTML 转义防 XSS，url/img 仅允许 http/https 或站内 / 路径。

**轮播图管理**：后台"图书业务 → 轮播图管理"可增删改前台轮播（标题/副标题/上传图片/跳转链接/排序/启用停用），前台自动加载（无图显示渐变+文字，接口失败回退默认 3 张）。

**弹窗交互**：前台所有弹窗点击遮罩空白处自动关闭。

**前台数据条与新书角标**：横幅下方实时统计（馆藏/读者/今日借出/今日订单，匿名接口）；近 7 天入库图书显示"🆕 新"角标。

## 24. 新功能演进（2026-08-18）

第四批功能迭代，围绕**搜索体验**与**操作即时反馈**：

### 24.1 搜索联想（百度式下拉）

前台搜索框输入时自动弹出匹配书名（`.nav-search` 下方下拉层）：

- 输入即联想，**防抖 200ms** 触发 `/system/book/suggest?keyword=`（匿名接口，在架书按书名模糊匹配，最多 8 条）
- **↑ / ↓** 键上下选择、**Enter** 选中或直接搜索、**Esc** 关闭、点击联想项直接搜索
- 中文输入法**组词中不触发**（`compositionstart/end` 处理，避免拼音中间态频繁请求）
- 请求序号防覆盖（`suggestReqSeq`），失焦/点击外部时失效在途请求，防止晚到响应重新弹出下拉

### 24.2 搜索结果排序 + 无结果引导 + 荐购

**排序**（结果标题行三个 Tab）：

- 综合（默认）/ 借阅最多（`borrowCount` 降序）/ 最新出版（`publish_date` 降序）
- 列表查询新增派生字段 `borrowCount`（借阅记录实时统计），后台图书列表同样可见该排序能力
- 排序字段走**白名单**校验（`BookController.list`），防 ORDER BY 注入

**无结果引导**：搜索无结果时不再显示空页，而是引导卡片——"没找到这本书，试试其他关键词，或告诉我们你想看什么书" + **「申请荐购」** 按钮。

**荐购管理**：

- 前台弹窗提交想看的书（书名必填/作者/附言），匿名接口 `POST /system/purchase/apply`，**同一书名待处理时拒绝重复提交**
- 新表 `book_purchase_req`（幂等建表，`business_init.sql` 与增量脚本 `upgrade_20260818_purchase.sql` 均含）
- 后台"图书业务 → 荐购管理"处理（待处理/已处理/已拒绝，可删除），权限 `system:purchase:*`

### 24.3 前台乐观 UI（点击瞬间响应）

借书 / 续借 / 预约点击后**按钮立即变态**（借阅→已借出、续借→已续借、预约→已预约），不等后端返回，出错再自动回滚，让用户感觉"系统反应真快"：

- **锁粒度按书拆分**：借书用 `pendingBorrow`、预约用 `pendingReserve`（以 bookId 为键的 Set）、续借用 `renewPending`（以 borrowId 为键），同一本书防重复提交，但**不同书可并行操作**，互不阻塞
- **失败回滚**：请求失败还原按钮态 + 移除乐观标识 + 重新拉取真实数据自愈（若后端实际已落库，刷新会正确恢复）
- 网格卡片与详情弹窗按钮状态联动（`renderBooks` 统一渲染）

### 24.4 后台上下架拨动开关

后台"图书信息"列表**状态列改为开关**，拨动即上架/下架，无需进编辑页：

- 有修改权限（`system:book:edit`）显示开关，否则只读标签
- **乐观切换** + 失败自动回滚；在途防重守卫（连续快速拨动忽略第二次）
- **联动校验**：有"预约中/可借"预约的图书**禁止下架**（`changeBookStatus` 锁行 + 检查预约，与删除图书的校验一致），避免读者约了书却被管理员悄悄下架

### 24.5 数据库升级约定

- `business_init.sql` 顶部含建表语句，**只用于全新库**初始化（旧库整文件导入会报"表已存在"）
- **已有库升级**执行增量脚本 `sql/upgrade_20260818_purchase.sql`（荐购表 + 荐购管理菜单，幂等）

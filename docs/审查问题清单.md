## 一、🔴 高优先级 —— 功能故障（前台主路径断裂）

### 1. ☐ 8 个页面的登录/注册必然失败（参数名 `name` ≠ 后端 `readerName`）
- **位置**：article.html:204,242 ｜ about.html:234,272 ｜ industry.html:236,274 ｜ join.html:224,262 ｜ news.html:229,267 ｜ policy.html:261,299 ｜ talent.html:189,227 ｜ service.html:212,249
- **问题**：这些页面提交 `new URLSearchParams({ name: name, cardNo: card })`，而后端 `ReaderController.login/register`（ReaderController.java:110,154）绑定的参数名是 `readerName`。`name` 不会被绑定 → 后端永远返回「请输入姓名和借书证号」。
- **来源**：提交 `0a34cbfd`（service.html）与 `60f217d6`（7 个内容页）复制登录弹窗时写错；home.html 和 services.html 用的是正确的 `readerName`。
- **影响**：除首页/服务列表外，全站登录、注册全部不可用——这是核心转化路径。
- **修法**：8 处 `name:` 改为 `readerName:`；建议抽成共享 `shared.js` 收敛，避免双版本再漂移。

### 2. ☐ 7 个内容页「后台管理」菜单点击报 ReferenceError（`goAdmin` 被嵌套进 `submitLogin` 内部）
- **位置**：article.html:213 ｜ about.html:243 ｜ industry.html:245 ｜ join.html:233 ｜ news.html:238 ｜ policy.html:270 ｜ talent.html:198
- **问题**：`function goAdmin() { location.href = '/index'; }` 被误粘贴进 `submitLogin()` 的成功分支里，成了函数局部声明，不会挂到全局。导航「更多 → ⚙️ 后台管理」的 `onclick="goAdmin()"` 点击即抛 `goAdmin is not defined`。（home.html:994、services.html:819 是顶层定义，正常。）
- **修法**：把 `goAdmin` 移到脚本顶层（与 `closeModal` 并列）。

### 3. ☐ home.html 残留引用不存在的 `#bookGrid`，点 logo / 登录成功 / 退出登录都会抛 TypeError
- **位置**：home.html:593,607,622,629,638（`document.getElementById('bookGrid').innerHTML = ...`）
- **触发点**：`:13` logo `onclick="resetAll()"` → `resetAll` → `loadBooks`；`:798` 登录成功回调；`:815` logout；以及 697,710,732,744,920 多条路径。
- **问题**：04 服务区块静态化后页面里已没有 `id="bookGrid"` 元素。初始化序列恰好没调 `loadBooks` 所以首屏不炸，但上述操作必炸——logo 点击完全失效。
- **修法**：删除整段服务列表死代码（`loadBooks/renderBooks/optimisticBorrow/optimisticReserve/openReserve/resetAll` 及 STATS_API/PUBLIC_STATS_API/RELATED_API/authParams 等死常量）；logo 改为滚回顶部或 `location.href='home.html'`。

### 4. ☐ 7 个内容页弹窗「点遮罩关闭」失效（共享脚本写在弹窗 DOM 之前）
- **位置**：article.html:266（及 about/industry/join/news/policy/talent 同模式）
- **问题**：`document.querySelectorAll('.modal').forEach(...)` 执行时 `#loginModal/#regModal/#toast` 还未被解析（它们在脚本之后），绑定落空。
- **修法**：脚本移到 `</body>` 前，或改用事件委托 `document.addEventListener('click', e => { if (e.target.classList.contains('modal')) ... })`。

### 5. ☐ 栏目页登录态显示错字段 + 无登出入口
- **位置**：article.html:225 ｜ about.html:255 ｜ industry.html:257 ｜ join.html:245 ｜ news.html:250 ｜ policy.html:282 ｜ talent.html:210
- **问题**：`renderLoginState` 用 `currentUser.name`，后端返回字段是 `readerName`（ReaderController.java:143）→ 即使修好 #1 也只会显示兜底值「成员」；且已登录状态点击自己名字弹出的是「成员注册」表单，这 7 个页面没有任何登出途径（home/services 有 `logout()`）。
- **修法**：改 `currentUser.readerName` 并提供退出按钮（清 `localStorage.shopUser` 即可，与 home 一致）。

## 二、🔴 高优先级 —— 安全

### 6. ☐ JWT 密钥默认值公开在仓库里，且当前 `.env` 的 `TOKEN_SECRET` 为空 → 可伪造管理员 token
- **位置**：application.yml:115、docker-compose.yml（TOKEN_SECRET 兜底值）、.env（与 .env.example 完全相同，`TOKEN_SECRET=` 空）
- **问题**：compose 的 `${TOKEN_SECRET:-25a96a…}` 对空串也回退默认 → 生产实际使用仓库里公开的密钥。任何能读到仓库的人可自签管理员 HS512 token，直接接管后台。叠加 README 公开文档化的 admin/admin123，风险闭环。
- **修法**：立即生成随机强密钥写入 `.env`；后端启动时校验密钥等于已知默认值则拒绝启动；历史镜像重建。

### 7. ☐ pre-commit 钩子把含 PII 的数据库快照自动提交进（可能公开的）GitHub 仓库
- **位置**：.githooks/pre-commit（每次 commit 导出全部业务表）→ sql/data_snapshot.sql
- **现状**：快照含 `reader` 表全部姓名/手机号/邮箱（含作者账号行 `Jerry / 138****0000 段演示号 / j***@qq.com`，标注「项目作者账号」）、`book_purchase_req` 申请人信息；origin/master 已同步。仓库是否公开未能联网核实（本机网络受限），**请自行确认**。
- **影响**：真实用户在前台注册后，其手机号/邮箱会在下一次 commit 时被自动推上 GitHub——隐私泄露管道。
- **修法**：短期从快照排除 `reader`/`book_purchase_req`（或脱敏）；长期改为示例数据文件与生产数据分离；若仓库公开且已有真实数据，需清理 git 历史。

### 8. ☐ 默认口令面 + 端口发布
- **位置**：docker-compose.yml（3306:3306、6379:6379 发布宿主机；MYSQL_ROOT_PASSWORD 默认 password；Redis 默认无密码）；README/docs 明文 admin/admin123
- **影响**：主机若有公网 IP/弱防火墙，数据库可直接远程 root/password 登录。
- **修法**：公网部署改 `expose` 内部网络或绑 127.0.0.1；强制首次改 admin 密码；Redis 设密码。

### 9. ☐ CORS 全开放（上一轮 H6，仍未修）
- **位置**：ruoyi-framework/.../ResourcesConfig.java:61 `addAllowedOriginPattern("*")`
- **修法**：公网部署收窄为站点自身 origin。

### 10. ☐ 「补办报名证」可凭姓名+手机号接管他人前台身份，且成功尝试不计数
- **位置**：ReaderController.java:194-234（applyReissue）、ReaderSessionServiceImpl（频控只记失败）
- **问题**：命中即作废旧证号并把新证号直接返回给调用者——知道某人姓名+登记手机号即可接管（新证号=登录凭证）。失败有 IP 频控，但**成功猜测不消耗频控额度**，可换 IP 慢速爆破。
- **修法**：新证号改发到登记邮箱而非接口返回；频控对「成功次数」也设上限。

### 11. ☐ `/system/config/configKey/{key}` 匿名开放，可枚举任意系统配置值
- **位置**：SysConfigController.java:73-79（@Anonymous 无 key 白名单）
- **影响**：当前库内 key 均无害，但管理员今后存入敏感参数即匿名可见。
- **修法**：白名单放行（如仅 `book.stock.warn`），其余要求权限。

### 12. ☐ sessionToken 经 GET 查询串传输（上一轮 H1，仍未修）
- **位置**：home.html:497,510,888,947 ｜ services.html:299,312,713,772 ｜ service.html:280,291
- **影响**：凭证落入 Nginx/后端访问日志、浏览器历史、代理缓存。
- **修法**：改请求头（如 `X-Session-Token`）或 POST body；顺带做 resolve 滑动续期。

## 五、✅ 已核实无问题（本轮验证过，无需动）

- **XSS 主战场安全**：article.html 正文 textContent + URL 白名单片段；news/policy/home 摘要先去标签再 esc；banner 全字段 esc + data-link 事件委托；后端 BbCodeUtil 先 escapeHtml4 再渲染白名单标签。
- **SQL 注入**：业务 mapper 无 `${}`（仅框架 dataScope）；orderBy 双层防护（SqlUtil 字符白名单 + BookController 列名白名单）。
- **认证设计**：登录防枚举（统一错误文案）+ IP+证号频控；证号 SecureRandom 不可预测；停用证号拒绝登录。
- **并发正确性**：borrowByCard 带 READ_COMMITTED 事务 + FOR UPDATE（自调用事务绕过问题有注释规避）；候补超时 CAS 推进；逾期标记条件更新。
- **前台一致性**：fetch 前缀全站统一 `/prod-api`（dev/prod 均配好代理）；localStorage 键统一 `shopUser`；导航链接/锚点完整；shop.html/book-system/万事屋 在前台与脚本零残留（dist 除外，见 #26）。
- **根路径路由**：nginx `location = / → /home.html`、dev before 钩子、后台走 `/index` 三处一致。

> 面向开发学习与演示场景，覆盖：本机启动 → 正式部署 → 数据库备份恢复 → 升级回滚

## 一、本机开发环境启动（每天开工）

依赖已装好的环境：**JDK 17、Maven、MySQL 8、Redis、Node.js**

1. 启动 MySQL 和 Redis（若没开机自启）
2. 启动后端：
   ```bash
   cd OPC
   mvn -pl ruoyi-admin -am package -DskipTests   # 修改代码后需重新打包
   java -jar ruoyi-admin/target/ruoyi-admin.jar   # 默认 8080 端口
   ```
3. 启动前端（开发模式，代码改动自动生效）：
   ```bash
   cd ruoyi-ui
   npm run dev
   ```
4. 访问：
   - 后台：`http://localhost:端口/`（admin / admin123（upgrade_20260828_01 统一））
   - 官网前台：`http://localhost:端口/`（根路径直达首页，旧链接 /home.html 仍可用）

> ⚠️ 端口以 `ruoyi-ui/vue.config.js` 中的 `port` 为准（默认 80，被占用时可改）。

## 二、正式部署（把系统拿出去给别人用）

部署到一台**公网服务器**（Windows / Linux 均可），核心三步：**数据库 → 后端 jar → 前端静态文件**。

### 1. 数据库（服务器上装 MySQL 8 + Redis）

```bash
# ① 建库（全部 SQL 无 USE 语句，均依赖命令行传库名；R-N3 修复：原文档命令缺库名会报 No database selected）
mysql --default-character-set=utf8mb4 -uroot -p -e "CREATE DATABASE IF NOT EXISTS \`ry-vue\` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci"
# ② 依次导入全部脚本（顺序不能乱；R22 修复：原文档只写 3 个脚本，
# 遗漏 role_init（editor 角色）/upgrade 链（CMS 表/菜单/回收站两态等全部结构变更）/
# data_snapshot（业务数据），按旧文档手动部署 = CMS 全缺、editor 缺失）
# 务必带 --default-character-set=utf8mb4：Windows 终端默认 GBK，
# 不带会把 UTF-8 中文读坏入库（菜单乱码 → 登录后报 getParentId 空指针）
mysql --default-character-set=utf8mb4 -uroot -p ry-vue < sql/ry_20260417.sql
mysql --default-character-set=utf8mb4 -uroot -p ry-vue < sql/quartz.sql
mysql --default-character-set=utf8mb4 -uroot -p ry-vue < sql/business_init.sql
mysql --default-character-set=utf8mb4 -uroot -p ry-vue < sql/role_init.sql
# 全部幂等升级脚本（通配扫描，文件名序=执行序；CMS 表/菜单/角色授权均在此链中）
for f in sql/upgrade_*.sql; do mysql --default-character-set=utf8mb4 -uroot -p ry-vue < "$f"; done
# 业务数据快照（文章/区块/栏目/页面/配置；幂等 REPLACE 可重复执行）
mysql --default-character-set=utf8mb4 -uroot -p ry-vue < sql/data_snapshot.sql
```

### 2. 后端（打包成 jar，随系统启动）

```bash
mvn -pl ruoyi-admin -am package -DskipTests
```

**推荐用环境变量启动**（U-9：不用改 git 跟踪的配置文件，避免弄脏工作区）：

```bash
# 数据库/Redis/JWT 全部经环境变量注入（与 docker-compose 等价）；TOKEN_SECRET 必须非空
export DB_HOST=localhost DB_PORT=3306 DB_USERNAME=root DB_PASSWORD=你的密码
export REDIS_HOST=localhost REDIS_PORT=6379
export TOKEN_SECRET=你的强随机密钥        # 参考 .env（start-all 脚本会自动生成）
export RUOYI_PROFILE=$HOME/ruoyi/uploadPath
java -jar ruoyi-admin/target/ruoyi-admin.jar
```

也可直接改配置文件后启动：

| 配置文件 | 改什么 |
|---|---|
| `ruoyi-admin/src/main/resources/application-druid.yml` | 数据库地址 / 账号 / 密码 |
| `ruoyi-admin/src/main/resources/application.yml` | 服务端口（默认 8080） |

```bash
java -jar ruoyi-admin/target/ruoyi-admin.jar
```

> 💡 长期运行建议用 NSSM 把 jar 注册成 Windows 服务（`nssm install 创新工场后端 "java" "-jar 路径\ruoyi-admin.jar"`），开机自启、崩溃自动拉起。

### 3. 前端（构建静态文件 + Nginx）

```bash
cd ruoyi-ui
npm install
npm run build:prod        # 生成 dist/ 静态文件
```

把 `dist` 目录放到服务器，Nginx 配置示例（Linux）：

```nginx
server {
    listen 80;
    server_name 你的域名或IP;

    # 前端页面
    location / {
        root /www/opc/dist;
        try_files $uri $uri/ /index.html;
    }

    # 后端接口代理（前端请求 /prod-api 前缀）
    location /prod-api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 上传的封面图片（后端本地存储）
    location /profile/ {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

> 💡 Windows 服务器也可以直接用 Nginx for Windows，配置相同。

## 三、数据库备份与恢复（重要！）

### 备份（每天一次，挂定时任务）

`scripts/backup-db.bat` 一键备份整个业务库，备份文件带日期时间戳：
`backup\ry-vue_20260813_0945.sql`

**设置每天自动备份（Windows）**：
1. 按 `Win + R` → 输入 `taskschd.msc` 打开"任务计划程序"
2. 右侧"创建基本任务" → 名称"官网数据库备份"
3. 触发器选"每天"、时间设为 23:00
4. 操作选"启动程序" → 程序选 `scripts\backup-db.bat`
5. 完成。以后每天 23 点自动生成一份备份

**建议**：定期把 `backup` 文件夹复制到 U 盘 / 网盘，防止硬盘损坏丢数据。

### 恢复（出问题时）

```bash
# G-3 fix: 备份为单库导出（无 CREATE DATABASE），恢复需指定库名（先建库见上方手动部署 ①）
mysql --default-character-set=utf8mb4 -uroot -p ry-vue < backup\ry-vue_20260813_0945.sql
```

> ⚠️ 恢复会**覆盖当前数据**，恢复前务必先备份一次现场数据。

## 四、升级与回滚

本项目所有改动都提交在 Git 里，升级 = 拉最新代码重新打包：

```bash
git pull origin master      # 拉取最新代码
mvn -pl ruoyi-admin -am package -DskipTests   # 重新打包后端
cd ruoyi-ui && npm run build:prod              # 重新构建前端
```

**数据库结构有变化时**（例如新表、新字段），按下面的方式处理（注意：`business_init.sql` 顶部含建表语句，只面向**全新库**初始化；旧库直接整文件导入会报"表已存在"，需用增量升级脚本）：

- **全新库**：依次导入 `sql/ry_20260417.sql`、`sql/quartz.sql`、`sql/business_init.sql`、`sql/role_init.sql` → **全部 `upgrade_*.sql`**（通配扫描）→ `sql/data_snapshot.sql`（完整清单以 `docker/mysql-init.sh` 为唯一权威来源）
- **已有旧库**：执行增量升级脚本（幂等，按版本顺序；**完整清单以 `docker/mysql-upgrade.sh` 为唯一权威来源**，Windows 端 `scripts/start-all.bat` 已同步）：
  - ⚠️ **Docker 部署陷阱（2026-08-27 实测）**：`docker compose up` 时 MySQL 容器若检测到数据卷已有数据，会**跳过 `/docker-entrypoint-initdb.d/` 全部初始化脚本（含升级脚本）**——旧卷只升级镜像不会升级数据库（表现为新功能报 `Unknown column`）。升级步骤必须是：①`docker compose exec -T mysql mysql --default-character-set=utf8mb4 -uroot -p ry-vue < sql/upgrade_*.sql`（G-3 fix 补库名：脚本已无 USE，不带库名报 No database selected；`-T` 禁 TTY 防管道中断；按序执行全部增量脚本）或 ②确认无保留数据后 `docker compose down -v` 重建卷（会清空数据库，仅限演示环境）。
  - `sql/upgrade_20260818_01_purchase.sql` 起至 `sql/upgrade_20260826_01_policy.sql`：入驻申请/邮件/回收站两态/认证/大赛/政策等（各脚本头有说明）
  - `sql/upgrade_20260825_02_menu_reorg.sql`：后台菜单业务导向四分组（内容运营/成员与报名/运营辅助/系统设置）
  - `sql/upgrade_20260825_03_recycle_cleanup.sql` + `recycle_restore.sql`：回收站入口清理与恢复（两脚本按序执行，终态为恢复）
  - `sql/upgrade_20260825_05_editor_fix.sql`：**补建 14 个缺失按钮权限菜单 + editor 角色按新目录结构重授**（必须在 menu_reorg 之后执行；全新库由 mysql-init.sh 自动执行）

**回滚** = 用 Git 历史回到上一个可用版本：

```bash
git checkout 上一个提交号   # 例如 git checkout bce94ff1
```

## 五、进阶：Docker 部署（可选）

> 适用：想一键启动整套环境（MySQL + Redis + 后端 + 前端），或在 Linux 服务器快速部署。
> 项目已内置完整 Docker 化文件，一条命令启动，无需手动打包。

### 项目内已包含的 Docker 文件

| 文件 | 作用 |
|---|---|
| `docker-compose.yml` | 编排 MySQL + Redis + 后端 + 前端 4 个容器，含健康检查与依赖等待 |
| `Dockerfile` | 后端镜像（多阶段：Maven 构建 → JRE 运行，含字体/时区） |
| `ruoyi-ui/Dockerfile` | 前端镜像（Node 构建 dist → Nginx 托管） |
| `docker/nginx.conf` | 前端页面 + `/prod-api` 代理到后端 + `/profile` 封面图片 |
| `docker/mysql-init.sh` | 首次启动按依赖顺序导入 SQL（系统表→定时任务→业务表→角色权限→**全部 upgrade 幂等脚本**→业务数据快照） |
| `docker/mysql-upgrade.sh` | 旧数据卷增量升级：对已有 mysql-data 卷补跑全部 upgrade 脚本（幂等） |
| `.dockerignore` | 排除 target/node_modules 等，加速构建 |

> 后端配置（`application-druid.yml`/`application.yml`）已支持环境变量覆盖：本机不设环境变量时行为不变，容器内由 compose 注入 `DB_HOST=mysql`、`REDIS_HOST=redis` 等。

### 一键启动

```bash
# 在项目根目录
docker compose up -d --build     # 全新部署（无旧数据卷时自动全量初始化）
# 或直接用已推送镜像（免构建）：先确保 .env 已设置 TOKEN_SECRET（跑一次 scripts\start-all 自动生成，
# 或 openssl rand -hex 32 写入 .env）——compose 对缺失 TOKEN_SECRET 直接报错（防默认密钥），
# 然后 docker compose up -d（当前版本 v2.4）
```

首次启动自动完成：建库 → 按序导入 SQL（系统表→业务表→**全部幂等升级脚本**→**业务数据快照**）→ 启动后端 → 构建并启动前端。之后访问：

- 后台管理：`http://服务器IP/`（/index 路由，admin / admin123（upgrade_20260828_01 统一））
- 官网前台：`http://服务器IP/home.html`
- 后端不对外映射 8080（仅容器内网，nginx 代理 /prod-api 与 /profile）

> ✅ **全新部署一致性已验证（2026-08-28）**：全新数据卷模拟完整部署 → 10 张核心表与本地逐项一致（cms_page 7 / cms_block 43 / cms_article 15 / sys_menu 153 / sys_role_menu 68 / sys_role 3 / sys_config 33 / sys_banner 3 / sys_notice 3 / cms_category 9），菜单图标零缺失、hero 配置齐全、admin 口令 admin123。**业务数据经快照继承；菜单/角色由升级脚本按名称定位（不依赖 menu_id，跨库安全）。**
> 🔄 **旧数据卷升级**：已有部署不会自动重跑初始化 → 执行 `bash docker/mysql-upgrade.sh`（对现有卷补跑全部幂等升级脚本，不动业务数据）；或 `docker compose exec -T mysql mysql --default-character-set=utf8mb4 -uroot -p ry-vue < sql/upgrade_*.sql` 按序执行（G-3 fix 补库名）。

### 常用命令

```bash
docker compose logs -f backend     # 看后端日志
docker compose down                # 停止（保留数据卷）
docker compose down -v             # 停止并删除数据（mysql-data/redis-data/upload 卷）
```

### 说明

- **上传文件持久化**：封面上传目录挂载在 `upload` 卷，容器重建不丢失
- **数据库持久化**：`mysql-data` 卷保存数据。全新库按 `docker/mysql-init.sh` 的依赖顺序自动导入（ry_20260417 → quartz → business_init → role_init → 各 `upgrade_2026*.sql` 幂等升级脚本，**含 `upgrade_20260824_03_two_state.sql` 回收站两态加列**）；存量库升级按日期顺序手动执行 `sql/upgrade_2026*.sql`（全部幂等，可重复执行）
- **邮件通知（自动）**：新成员登记必填邮箱，报名/候补/入驻申请等节点自动发邮件。发件人邮箱与授权码均**通过环境变量注入**（勿写进代码/镜像）：`docker-compose.yml` 已在 backend 的 `environment` 内置 `${MAIL_USERNAME:-}` / `${MAIL_AUTH_CODE:-}` / `${MAIL_ENABLED:-true}`——**部署时在 docker-compose.yml 同目录建 `.env` 文件**写入 `MAIL_USERNAME=你的发件邮箱` 与 `MAIL_AUTH_CODE=你的邮箱授权码`，`docker compose up` 自动读取；不建则邮件不发送、业务不受影响；不需要邮件通知可设 `MAIL_ENABLED=false`
- **改默认密码**：公网部署前务必修改 admin 密码（系统管理 → 用户管理）
- **Druid 监控台**：**默认关闭**（`application-druid.yml` 的 `statViewServlet.enabled: ${DRUID_STAT_ENABLED:false}`）；如需排查慢 SQL，设 `.env` 的 `DRUID_STAT_ENABLED=true` 并**务必一并修改** `DRUID_USERNAME`/`DRUID_PASSWORD`（默认 `ruoyi/123456` 为公开演示口令），生产再配 `allow` 白名单或保持 `/druid/**` 需登录
- **国内拉取基础镜像**：Docker Hub 直连常被墙，`docker compose up` 卡在拉取 mysql/redis 等基础镜像时，需配置镜像加速：
  - Docker Desktop → Settings → Docker Engine → 在 JSON 中加入 `"registry-mirrors": ["https://docker.1panel.live", "https://docker.m.daocloud.io"]` → Apply & Restart
  - 或先手动拉取再改 tag（免改配置）：`docker pull docker.1panel.live/library/mysql:8.0 && docker tag docker.1panel.live/library/mysql:8.0 mysql:8.0`（redis/nginx/node/eclipse-temurin/maven 同理）
- **全新库初始化已验证**：2026-08-18 在 Docker 环境实测全量初始化通过（book 21 行 / shop_order 4 行 / 菜单 102 项）；2026-08-27~28 连续多轮变更后由 `upgrade_20260827_01~09` + `upgrade_20260828_01` 幂等覆盖（admin 口令统一、菜单图标、服务回收站隐藏、两级栏目示例等），通配扫描保证新库自动同步。`business_init.sql` 曾存在 2 个仅在全新库初始化时必现的缺陷（book 表 INSERT 无列名导致 1136、shop_order 建表晚于插数据导致 1146），均已修复
- 本机开发不需要 Docker（已有全套环境）；Docker 主要面向**服务器部署**与**环境复现**

## 七、常见问题排查

| 现象 | 检查 |
|---|---|
| 页面打不开 | 前端 npm run dev 是否在运行；端口是否被占用 |
| 接口 404/502 | 后端是否启动；Nginx 代理地址是否正确 |
| 缓存监控报"cannot read redis info" | Redis 安装路径不能含中文/反斜杠转义问题，建议装到 `C:\Redis` |
| 中文乱码 | 数据库连接串加 `characterEncoding=utf8`；导入 SQL 用 `--default-character-set=utf8mb4` |
| 上传图片后前台不显示 | 确认 `/profile/` 代理配置（Nginx 段）或前端 /dev-api 前缀 |

## 附录：认证与邮件改造后的部署要点（2026-08-24）

设计决策与邮件模板见《开发文档》十六、附录（M1-M5 已实施，`sql/upgrade_20260824_04_auth.sql` 需先执行）。

### 1. 升级脚本
- 执行 `sql/upgrade_20260824_04_auth.sql`（幂等，可重跑）：mail_config/mail_template 建表 + 10 个模板初始数据、reader 加认证列（password_hash/pwd_set/email_verified/phone_verified/last_login_time）、reader_login_log 审计表、reader.email 唯一索引、菜单与 sys_config。

### 2. 邮件通知（后台可配，不再依赖环境变量）
- 登录后台 → 「系统管理 → 邮件通知」填写发件邮箱 + SMTP 授权码 → 点「测试发送」验证 → 保存即生效（无需重启）。
- 未在后台配置时自动回退环境变量（MAIL_USERNAME / MAIL_AUTH_CODE），行为与改造前一致。
- **SMTP 授权码加密**：建议在 .env 设置 `MAIL_SECRET_KEY`（任意长随机串，如 `openssl rand -hex 32`）。未设置时授权码明文入库，后台页面会显示黄色警告。
- 10 个邮件模板（注册成功/验证码/报名/续期/候补/入驻等）均可在「邮件通知 → 邮件模板」页编辑，占位符 `{readerName}` `{cardNo}` 等自动替换，停用/删除时回退内置默认模板。

### 3. 成员认证（证号 + 密码）
- 新成员注册 = 资料+密码 → 邮箱验证码 → 完成（注册成功邮件只发证号，**不发密码明文**）。
- 存量成员（改造前登记、无密码）首次登录会收到引导，走「忘记密码 → 邮箱验证码 → 设置密码」；管理员也可在成员列表点「重置密码」（发验证码）或通过「设置密码」接口直接代设。
- 会话为 14 天滑动续期（sys_config `reader.session.minutes`，默认 20160），个人主页「账号安全」可改密/改邮箱/管理登录设备。

### 4. 生产建议（真实环境）
- **HTTPS 必配**：云服务器反代/Nginx 启用 TLS；验证码、密码等敏感信息仅允许经 HTTPS 传输。
- **邮件送达率**：若使用自有域名邮箱（非 QQ 个人邮箱），按邮箱服务商要求配置 **SPF / DKIM / DMARC** 记录，否则验证码邮件易进垃圾箱。
- 登录审计：读者端登录/改密等事件写入 `reader_login_log`，后台成员列表页可查；建议定期巡检异常 IP。
- 密码策略已内置（≥10 位、至少 3 类字符），如需调整联系开发者改 `PasswordStrength` 常量。

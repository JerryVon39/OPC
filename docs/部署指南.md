# 🛡️ 数智游民创新工场官网 · 部署与运维指南

> 面向开发学习与演示场景，覆盖：本机启动 → 正式部署 → 数据库备份恢复 → 升级回滚

---

## 一、本机开发环境启动（每天开工）

依赖已装好的环境：**JDK 17、Maven、MySQL 8、Redis、Node.js**

1. 启动 MySQL 和 Redis（若没开机自启）
2. 启动后端：
   ```bash
   cd RuoYi-Vue
   mvn -pl ruoyi-admin -am package -DskipTests   # 修改代码后需重新打包
   java -jar ruoyi-admin/target/ruoyi-admin.jar   # 默认 8080 端口
   ```
3. 启动前端（开发模式，代码改动自动生效）：
   ```bash
   cd ruoyi-ui
   npm run dev
   ```
4. 访问：
   - 后台：`http://localhost:端口/`（admin / admin123）
   - 官网前台：`http://localhost:端口/`（根路径直达首页，旧链接 /home.html 仍可用）

> ⚠️ 端口以 `ruoyi-ui/vue.config.js` 中的 `port` 为准（默认 80，被占用时可改）。

## 二、正式部署（把系统拿出去给别人用）

部署到一台**公网服务器**（Windows / Linux 均可），核心三步：**数据库 → 后端 jar → 前端静态文件**。

### 1. 数据库（服务器上装 MySQL 8 + Redis）

```bash
# 全新服务器初始化：依次导入三个脚本（顺序不能乱；business_init.sql 面向全新库，含建表+数据）
# 务必带 --default-character-set=utf8mb4：Windows 终端默认 GBK，
# 不带会把 UTF-8 中文读坏入库（菜单乱码 → 登录后报 getParentId 空指针）
mysql --default-character-set=utf8mb4 -uroot -p < sql/ry_20260417.sql
mysql --default-character-set=utf8mb4 -uroot -p < sql/quartz.sql
mysql --default-character-set=utf8mb4 -uroot -p < sql/business_init.sql
```

### 2. 后端（打包成 jar，随系统启动）

```bash
mvn -pl ruoyi-admin -am package -DskipTests
```

修改两个配置后启动：

| 配置文件 | 改什么 |
|---|---|
| `ruoyi-admin/src/main/resources/application-druid.yml` | 数据库地址 / 账号 / 密码 |
| `ruoyi-admin/src/main/resources/application.yml` | 服务端口（默认 8080） |

```bash
java -jar ruoyi-admin/target/ruoyi-admin.jar
```

> 💡 长期运行建议用 NSSM 把 jar 注册成 Windows 服务（`nssm install 创新工场后端 "java" "-jar 路径\ruoyi-admin.jar"`），开机自启、崩溃自动拉起。

### 3. 前端（构建静态文件 + Nginx）

```bash
cd ruoyi-ui
npm install
npm run build:prod        # 生成 dist/ 静态文件
```

把 `dist` 目录放到服务器，Nginx 配置示例（Linux）：

```nginx
server {
    listen 80;
    server_name 你的域名或IP;

    # 前端页面
    location / {
        root /www/opc/dist;
        try_files $uri $uri/ /index.html;
    }

    # 后端接口代理（前端请求 /prod-api 前缀）
    location /prod-api/ {
        proxy_pass http://127.0.0.1:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 上传的封面图片（后端本地存储）
    location /profile/ {
        proxy_pass http://127.0.0.1:8080;
    }
}
```

> 💡 Windows 服务器也可以直接用 Nginx for Windows，配置相同。

## 三、数据库备份与恢复（重要！）

### 备份（每天一次，挂定时任务）

`scripts/backup-db.bat` 一键备份整个业务库，备份文件带日期时间戳：
`backup\ry-vue_20260813_0945.sql`

**设置每天自动备份（Windows）**：
1. 按 `Win + R` → 输入 `taskschd.msc` 打开"任务计划程序"
2. 右侧"创建基本任务" → 名称"官网数据库备份"
3. 触发器选"每天"、时间设为 23:00
4. 操作选"启动程序" → 程序选 `scripts\backup-db.bat`
5. 完成。以后每天 23 点自动生成一份备份

**建议**：定期把 `backup` 文件夹复制到 U 盘 / 网盘，防止硬盘损坏丢数据。

### 恢复（出问题时）

```bash
mysql -uroot -p < backup\ry-vue_20260813_0945.sql
```

> ⚠️ 恢复会**覆盖当前数据**，恢复前务必先备份一次现场数据。

## 四、升级与回滚

本项目所有改动都提交在 Git 里，升级 = 拉最新代码重新打包：

```bash
git pull github master      # 拉取最新代码
mvn -pl ruoyi-admin -am package -DskipTests   # 重新打包后端
cd ruoyi-ui && npm run build:prod              # 重新构建前端
```

**数据库结构有变化时**（例如新表、新字段），按下面的方式处理（注意：`business_init.sql` 顶部含建表语句，只面向**全新库**初始化；旧库直接整文件导入会报"表已存在"，需用增量升级脚本）：

- **全新库**：依次导入 `sql/ry_20260417.sql`、`sql/quartz.sql`、`sql/business_init.sql`（含全部建表 + 数据 + 菜单）
- **已有旧库**：执行增量升级脚本（幂等，按版本顺序）：
  - `sql/upgrade_20260818_purchase.sql`：入驻申请表 + 入驻申请管理菜单
  - `sql/upgrade_20260819_menu.sql`：业务菜单重组（历史脚本，官网改造后已由 upgrade_20260821 改名覆盖）
  - `sql/upgrade_20260819_recycle.sql`：回收站（表 + 菜单 + librarian 角色关联）
  - `sql/upgrade_20260819_mail.sql`：成员/回收站/入驻申请表加 email 列（自动邮件通知）

**回滚** = 用 Git 历史回到上一个可用版本：

```bash
git checkout 上一个提交号   # 例如 git checkout bce94ff1
```

## 五、进阶：Docker 部署（可选）

> 适用：想一键启动整套环境（MySQL + Redis + 后端 + 前端），或在 Linux 服务器快速部署。
> 项目已内置完整 Docker 化文件，一条命令启动，无需手动打包。

### 项目内已包含的 Docker 文件

| 文件 | 作用 |
|---|---|
| `docker-compose.yml` | 编排 MySQL + Redis + 后端 + 前端 4 个容器，含健康检查与依赖等待 |
| `Dockerfile` | 后端镜像（多阶段：Maven 构建 → JRE 运行，含字体/时区） |
| `ruoyi-ui/Dockerfile` | 前端镜像（Node 构建 dist → Nginx 托管） |
| `docker/nginx.conf` | 前端页面 + `/prod-api` 代理到后端 + `/profile` 封面图片 |
| `docker/mysql-init.sh` | 首次启动按依赖顺序导入 SQL（系统表→定时任务→业务表→角色权限） |
| `.dockerignore` | 排除 target/node_modules 等，加速构建 |

> 后端配置（`application-druid.yml`/`application.yml`）已支持环境变量覆盖：本机不设环境变量时行为不变，容器内由 compose 注入 `DB_HOST=mysql`、`REDIS_HOST=redis` 等。

### 一键启动

```bash
# 在项目根目录
docker compose up -d --build
```

首次启动自动完成：建库 → 按序导入 SQL → 启动后端 → 构建并启动前端。之后访问：

- 后台管理：`http://服务器IP:8080/`（admin / admin123）
- 官网前台：`http://服务器IP:8080/`（根路径直达首页）
- 前端 Nginx 也在 80 端口：`http://服务器IP/`（/prod-api 与 /profile 已代理）

### 常用命令

```bash
docker compose logs -f backend     # 看后端日志
docker compose down                # 停止（保留数据卷）
docker compose down -v             # 停止并删除数据（mysql-data/redis-data/upload 卷）
```

### 说明

- **上传文件持久化**：封面上传目录挂载在 `upload` 卷，容器重建不丢失
- **数据库持久化**：`mysql-data` 卷保存数据；后续升级数据库变更需手动执行增量升级脚本（当前：`upgrade_20260818_purchase.sql` 入驻申请表+菜单、`upgrade_20260819_menu.sql` 菜单重组、`upgrade_20260819_recycle.sql` 回收站、`upgrade_20260819_mail.sql` 邮件 email 列）
- **邮件通知（自动）**：新成员登记必填邮箱，报名/候补/入驻申请等节点自动发邮件。发件人邮箱与授权码均**通过环境变量注入**（勿写进代码/镜像）：`docker-compose.yml` 已在 backend 的 `environment` 内置 `${MAIL_USERNAME:-}` / `${MAIL_AUTH_CODE:-}` / `${MAIL_ENABLED:-true}`——**部署时在 docker-compose.yml 同目录建 `.env` 文件**写入 `MAIL_USERNAME=你的发件邮箱` 与 `MAIL_AUTH_CODE=你的邮箱授权码`，`docker compose up` 自动读取；不建则邮件不发送、业务不受影响；不需要邮件通知可设 `MAIL_ENABLED=false`
- **改默认密码**：公网部署前务必修改 admin 密码（系统管理 → 用户管理）
- **Druid 监控台**：默认开启且口令为 `ruoyi / 123456`（`application-druid.yml`，允许所有 IP 访问 `/druid/*`）。本地/内网演示无碍；**公网部署前**务必修改 `login-username/login-password` 或设置 `allow` 白名单、`statViewServlet.enabled: false` 关闭
- **国内拉取基础镜像**：Docker Hub 直连常被墙，`docker compose up` 卡在拉取 mysql/redis 等基础镜像时，需配置镜像加速：
  - Docker Desktop → Settings → Docker Engine → 在 JSON 中加入 `"registry-mirrors": ["https://docker.1panel.live", "https://docker.m.daocloud.io"]` → Apply & Restart
  - 或先手动拉取再改 tag（免改配置）：`docker pull docker.1panel.live/library/mysql:8.0 && docker tag docker.1panel.live/library/mysql:8.0 mysql:8.0`（redis/nginx/node/eclipse-temurin/maven 同理）
- **全新库初始化已验证**：2026-08-18 在 Docker 环境实测全量初始化通过（book 21 行 / shop_order 4 行 / 菜单 102 项）。`business_init.sql` 曾存在 2 个仅在全新库初始化时必现的缺陷（book 表 INSERT 无列名导致 1136、shop_order 建表晚于插数据导致 1146），均已修复
- 本机开发不需要 Docker（已有全套环境）；Docker 主要面向**服务器部署**与**环境复现**

## 六、快速在线演示（cpolar 内网穿透）

> 适用：不想买服务器，临时把本机项目分享给别人（老师/同学/客户）在线访问。
> 原理：cpolar 客户端把本机端口映射到公网临时域名。本项目只需映射**前端端口**（如 8081），因为前端 dev server 内置代理会转发 `/dev-api` 到后端 8080，全链路自动打通。

### 步骤

1. **下载安装**：官网 `www.cpolar.com` 注册账号 → 下载 Windows 版 → 安装登录
2. **创建隧道**：隧道管理 → 创建隧道：
   - 协议：**HTTP**
   - 本地地址：**前端端口**（`ruoyi-ui/vue.config.js` 中的 port，如 8081）
   - 域名类型：免费版选随机域名
3. **启动隧道**：启动后获得公网地址（如 `https://xxxxxx.cpolar.top`）
4. **分享**：
   - 官网前台：`https://xxxxxx.cpolar.top/`（根路径直达首页）
   - 后台管理：`https://xxxxxx.cpolar.top/`（**仅限自己使用，不要外发**）

### 注意事项

- 免费版域名随机，**重启 cpolar 后地址会变**；固定域名需付费
- 公网暴露前务必**修改 admin 默认密码**（系统管理 → 用户管理）
- 前台页面已做**手机版适配**，手机打开公网链接自动显示移动版
- 演示期间本机需保持：MySQL + Redis + 后端 jar + 前端 dev server + cpolar 全部运行

## 七、常见问题排查

| 现象 | 检查 |
|---|---|
| 页面打不开 | 前端 npm run dev 是否在运行；端口是否被占用 |
| 接口 404/502 | 后端是否启动；Nginx 代理地址是否正确 |
| 缓存监控报"cannot read redis info" | Redis 安装路径不能含中文/反斜杠转义问题，建议装到 `C:\Redis` |
| 中文乱码 | 数据库连接串加 `characterEncoding=utf8`；导入 SQL 用 `--default-character-set=utf8mb4` |
| 上传图片后前台不显示 | 确认 `/profile/` 代理配置（Nginx 段）或前端 /dev-api 前缀 |

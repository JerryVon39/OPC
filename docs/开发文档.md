## 一、项目定位

清远市首个人工智能 OPC（One Person Company，一人公司）生态社区的官方网站。
前台展示社区服务/政策/新闻并提供成员注册、报名、候补、入驻申请；后台管理内容与数据。

**核心概念**：OPC = 一个人 + AI = 一家公司。成员（个人/团队/企业）是唯一主体，入驻申请是成员的一个动作。
**业务命名映射**（表/类沿用旧名）：`Book=服务`、`Reader=成员`、`BorrowRecord=报名`、`BookReserve=候补`、`BookPurchaseReq=入驻申请`

## 二、技术栈

| 层 | 技术 |
|---|---|
| 后端 | Java 17 + Spring Boot 3.x + RuoYi 框架改造（MyBatis + MySQL 8 + Redis） |
| 前端前台 | 纯静态 HTML/CSS/JS（`ruoyi-ui/public/`，无框架无构建，fetch 调接口） |
| 前端后台 | Vue 3 + Element Plus（`ruoyi-ui/src/`，RuoYi 标准管理端） |
| 部署 | Docker Compose（nginx + backend + mysql + redis）或本机脚本 |

> 12 页不再内嵌重复 JS：认证全套（两步注册/三标识登录/忘记密码/登出/会话过期引导）、
> 工具函数（`esc`/`toast`/`closeModal`/`apiFetch`）、登录态渲染、导航交互（汉堡菜单/

> （渲染/筛选/提交），登录/登出后的页面刷新用钩子 `window.AUTH_AFTER_LOGIN`/
> `AUTH_AFTER_LOGOUT` 扩展。**改动公共逻辑只改 site.js 一处，勿再向页面复制粘贴。**
> 页面结构约定：登录/注册/找回密码弹窗 HTML 全站同一份（services 版：三标识提示 +
> 登录/忘记密码/取消三按钮），新页面照 `about.html` 模板复制。

### ⚠️ 前台必守纪律（历史踩坑，勿回归）
1. **所有动态插值过 `esc()`**（标题/内容/分类等库数据）
2. **登录参数名是 `account`（证号/手机号/邮箱）+ `password`；注册参数名是 `readerName`**（不是 `name`——Spring 按参数名绑定，写错则登录/注册永远失败）
3. **会话凭证走 `X-Session-Token` 请求头**（不拼 URL query——会落日志）
4. **「个人主页」链接不要嵌进 `onclick="logout()"` 元素内**（点击事件冒泡触发登出）
5. **注册成功回调必须写登录态**（`currentUser = d.data; localStorage.setItem('shopUser', ...); renderLoginState();`）
6. **导航/页脚/登录弹窗改动 → 全站 12 页同步**（无公共组件，每页独立复制）
7. **页面 JS 语法校验**：`node -e "new Function(require('fs').readFileSync('xx.html','utf8').match(/<script>([\s\S]*?)<\/script>/s)[1])"`
8. **新增页面记得加**：og/canonical/favicon meta 标签、SEO description、汉堡菜单按钮

## 九、核心业务流程详解

### 1. 成员注册 → 自动登录
```
前台注册表单 → POST /reader/register → 后端 SecureRandom 生成 JS+8 位证号
→ 返回 {readerId, readerName, cardNo, email, sessionToken}
→ 前端写入 currentUser + localStorage('shopUser') + renderLoginState() → 已是登录态
```

### 2. 报名（防超卖）
```
POST /borrow/borrowByCard（X-Session-Token 头）
→ @Transactional(READ_COMMITTED) + SELECT ... FOR UPDATE 锁服务行
→ 校验 status='0'（招募中）+ stock > 0 → INSERT borrow_record + stock-1（CAS 条件更新）
→ 邮件通知报名成功
```

### 3. 候补与自动推进
```
满员时 POST /reserve/add → status='0'（候补中）排队
定时任务 BorrowTask.reserveExpireCheck（每天 8 点）：
  超 2 天未报名的「有名额」候补 → CAS 取消 → 推进该书最早候补人 → 邮件通知
```

### 4. 入驻申请挂账号
```
已登录提交 → apply 校验会话 → 按 cardNo 查 reader_id → 写入 book_purchase_req.reader_id
→ 个人主页「我的入驻申请」按 reader_id 查询展示审核状态
（匿名提交则不关联，历史数据 reader_id 为空）
```

## 十四、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 登录后点个人主页变未登录 | 链接嵌在 logout 元素内 | 链接独立于 logout span（已修勿回归） |
| 部署后页面是旧版 | dist 未重建 | `npm run build:prod` + 重建镜像 |
| 登录永远失败 | 参数名写成 name | 用 `readerName` |
| 注册后没自动登录 | register 回调没写登录态 | currentUser = d.data + localStorage + renderLoginState |
| 报名提示「图书库存不足」 | 后端旧文案 | 已统一「服务名额不足」（勿回归） |
| 中文乱码入库 | SQL 未带字符集 | `--default-character-set=utf8mb4` |
| 页面 JS 报错 | 某页语法坏 | node 校验该页 script（见五-纪律 7） |
| 后端启动失败提示 token.secret | .env 未设或为默认值 | 生成随机 96 位 hex 写入 .env |
| 邮件发不出 | 授权码错/未开 SMTP | QQ 邮箱设置 → 账户 → 开启 SMTP 服务 |
| 端口被占 | 上次未关干净 | `scripts/stop-local.bat` 或手动杀 java/node |

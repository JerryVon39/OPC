## 一、项目定位

清远市首个人工智能 OPC（One Person Company，一人公司）生态社区的官方网站。
前台展示社区服务/政策/新闻并提供成员注册、报名、候补、入驻申请；后台管理内容与数据。

**核心概念**：OPC = 一个人 + AI = 一家公司。成员（个人/团队/企业）是唯一主体，入驻申请是成员的一个动作。

## 二、技术栈

| 层 | 技术 |
|---|---|
| 后端 | Java 17 + Spring Boot 3 + RuoYi 框架改造（MyBatis + MySQL 8 + Redis） |
| 前端前台 | 纯静态 HTML/CSS/JS（`ruoyi-ui/public/`，无框架，fetch 调接口） |
| 前端后台 | Vue 3 + Element Plus（`ruoyi-ui/src/`，RuoYi 标准管理端） |
| 部署 | Docker Compose（nginx + backend + mysql + redis）或本机脚本 |

## 三、目录结构

```

│   ├── service/impl/     #   业务逻辑（并发控制、状态机、邮件通知）
│   └── resources/mapper/ #   MyBatis XML
├── ruoyi-ui/
│   ├── public/           # ⭐ 前台官网静态页（12 个 HTML + css/site.css）
│   └── src/              #   后台管理 Vue3 应用

├── docker/               # nginx.conf、mysql-init.sh
├── .githooks/pre-commit  # 提交前自动导出数据快照（已排除 PII 表）
```

**命名映射**（业务改造后，表/类仍用旧名）：
`Book=服务`、`Reader=成员`、`BorrowRecord=报名`、`BookReserve=候补`、`BookPurchaseReq=入驻申请`

## 四、本地启动（推荐 start-local.bat）

```bash
# Windows：双击 scripts\start-local.bat（需 JDK17 + Node + MySQL 本机）
# 或手动：
cd ruoyi-ui && npm install          # 首次
npm run dev -- --no-open --port=8081  # 前端 dev server
cd .. && mvn -pl ruoyi-admin -am package -DskipTests
java -jar ruoyi-admin/target/ruoyi-admin.jar  # 后端 8080
```

- 前台官网：`http://localhost:8081/home.html`
- 后台管理：`http://localhost:8081/`（admin / admin123，演示）
- 数据库：MySQL 库 `ry-vue`，配置见 `.env`（DB_PASSWORD 等）

## 五、数据库

- **初始化**：`sql/business_init.sql`（含建表 + 种子数据）
- **增量升级**：`sql/upgrade_YYYYMMDD_*.sql` 按日期顺序执行（幂等可重跑）
- **数据快照**：`.githooks/pre-commit` 每次 commit 自动导出业务表到 `sql/data_snapshot.sql`（已排除 reader/book_purchase_req 的 PII）
- **⚠️ 新增字段/表**：写 `sql/upgrade_YYYYMMDD_*.sql`，不要改 business_init.sql（历史库不重跑）

## 六、开发规范

### 前台静态页（ruoyi-ui/public/）
- **12 页结构**：home / services / service / article / about / industry / join / policy / talent / news / contest / profile
- **导航**：每页复制一份（汉堡菜单 ≤768px 收起），改导航需全站 12 页同步
- **接口前缀**：统一 `/prod-api`（dev/prod 代理已配好）
- **登录态**：localStorage `shopUser` 键存成员信息（含 sessionToken）
- **⚠️ 必守纪律**：
  1. 所有动态插值过 `esc()`（防 XSS）
  2. 登录/注册/入驻申请弹窗参数名是 `readerName`（不是 name）
  3. 会话凭证走 `X-Session-Token` 请求头（不拼 URL）
  4. 「个人主页」链接不要嵌进 `onclick="logout()"` 元素内（会点击即登出）
- **新增页面**：复制现有页改导航 + 内容，语法用 `node -e "new Function(script)"` 校验

### 后端
- **匿名接口**：`@Anonymous` 注解（SecurityConfig 放行），面向大众的公开接口用
- **前台会话**：`readerSessionService.create/resolveFromRequest`（30 分钟 TTL，Redis）
- **频控**：匿名敏感操作（login/register/apply）复用 `readerSessionService.isBlocked/recordFail` 按 IP 限流
- **并发**：报名/候补等写操作用 `@Transactional` + FOR UPDATE 行锁 + CAS 条件更新
- **文案**：用户可见消息用「服务/成员/报名」话术，勿用「图书/借书」

### 邮件通知
- 配置：`.env` 的 `MAIL_USERNAME`/`MAIL_AUTH_CODE`（QQ 邮箱 SMTP）
- 触发点：报名成功、候补成功、候补有名额、入驻申请处理结果

## 七、核心业务流

```
注册（自动登录）→ 浏览服务 → 报名 / 满员候补 → 个人主页查看状态
                                       ↓
               入驻申请（A 类合伙人/B 类成员，登录后自动挂账号）
```

| 流程 | 接口 | 说明 |
|---|---|---|
| 注册 | POST `/reader/register` | 返回 cardNo + sessionToken（注册即登录） |
| 登录 | POST `/reader/login` | 姓名 + 成员编号精确匹配，防枚举 |
| 服务列表 | GET `/book/list` | 匿名，分页/分类/排序 |
| 报名 | POST `/borrow/borrowByCard` | 需会话，FOR UPDATE 防超卖 |
| 候补 | POST `/reserve/add` | 满员排队，定时任务自动推进 |
| 入驻申请 | POST `/purchase/apply` | 登录自动挂 reader_id；匿名也可提交 |
| 我的报名/候补/申请 | GET `/borrow/queryByCard` `/reserve/myList` `/purchase/myList` | 需会话 |
| CMS 文章 | GET `/cms/publicList` `/cms/publicDetail/{id}` | 前台新闻/政策 |

## 八、部署

### Docker（推荐正式部署）
```bash
scripts/start-all.bat    # 或 docker compose up -d --build
# 前端 80 端口 nginx、后端 8080、MySQL/Redis 仅内网（expose）
```
**⚠️ 部署前必须**：`cd ruoyi-ui && npm run build:prod` 重新构建 dist（dist 不进 git，旧 dist 会导致前台页面/功能过时）

### 安全注意
- `.env` 设置强随机 `TOKEN_SECRET`（后端启动会校验非默认值，默认值直接拒绝启动）
- 公网部署前：改 admin 密码、MySQL root 密码、Redis 密码（当前为演示默认值）
- CORS 全开放（`ResourcesConfig.java`），公网需收窄为站点自身

## 九、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 登录后点个人主页变未登录 | 链接嵌在 logout 元素内（已修，勿回归） | 链接独立于 logout span |
| 部署后页面是旧版 | dist 未重建 | `npm run build:prod` + 重建镜像 |
| 报名提示「图书库存不足」 | 后端旧文案 | 已统一为「服务名额不足」（勿回归） |
| 注册后没自动登录 | register 返回值缺 sessionToken | 需后端 `ReaderController.register` 返回 |
| 中文乱码入库 | 执行 SQL 未带字符集 | `mysql --default-character-set=utf8mb4` |
| 页面 JS 报错 | 改 12 页某页语法坏了 | 用 node 校验该页 script |

## 十、给接手的开发者的第一步

3. 后台登录 admin/admin123，熟悉 CMS 文章/服务/轮播/入驻申请管理
4. 改代码前先看 `docs/审查记录.md`（历史问题与规范，避免回归）
